# 접수·공고·계약 통합 수집

기본 매핑은 [확정 필드 대응](json-field-mapping.md)을 구현한 `src/Pclm.Core/Erp/mapping.json`이다. JSON과 확장 입력은 같은 변환·미리보기·저장 경로를 사용한다. PDF 입구(PDF 드롭·폴더 가져오기·PDF 비교)는 걷었다(ADR-028) — 자료는 확장·JSON·계획 엑셀로만 들어온다.

## 메인 프로그램

1. **설정 → 고급 · ERP 매핑과 JSON 가져오기**를 연다.
2. 자료를 읽은 화면의 프로필을 선택하고 JSON 파일을 연다. 받는 화면은 메뉴 번호의 허용 목록으로만 가리고, 화면 하나에
   프로필 하나다(ADR-037) — 목록은 기본 `mapping.json` 에서 `screen:{code, name}` 을 단 프로필이고, 같은 프로필이 그 화면의
   고유키(`identitySource`·`baseField`·`seqField`)를 든다. 번호가 목록에 있고 그 고유키가 읽혀야 받는다. 지금은 셋이다: 조달요구 접수 목록형(메뉴 01117)
   `g2b-request-v1`, 입찰공고 상세(01179) `g2b-notice-a-v1`, 계약 상세(01579) `g2b-contract-v1`. 파일은 `pointInfo` 의
   `depth3 → depth2 → depth1` 중 비지 않은 가장 깊은 단을 그 화면의 번호로 본다. 번호가 없거나 목록에 없으면 거절하고,
   프로필이 그 화면의 것이 아니면 맞는 프로필을 알려 준다. 나머지 프로필(`g2b-request-b-v1`·`g2b-notice-b-v1`·
   `g2b-public-notice-header-v1`)은 매핑에 남아 있지만 `screen` 이 없어 받지 않는다. 받는 화면을 넓힐 때는
   기본 `mapping.json` 의 그 프로필에 `screen` 을 달고 고유키·필드를 함께 맞춘다.
3. **활성 매핑으로 미리보기**를 누른다. 기존 품목과 새 원천 행의 키가 다르면 행 대응 또는 새 행 추가를 선택하고 다시 미리보기한다.
4. 기존값과 다른 값, 사라진 원천 행, 사용자 정정값은 각각 유지/적용을 선택한다. 선택하지 않은 충돌은 저장되지 않는다. 미수집 필드는 건드리지 않는다.
5. **검토한 자료 저장**을 누른다. 메인 목록도 갱신한다. 응답이 끊기면 같은 요청 결과 확인으로 재시도한다. 창을 닫았다면 이력과 현재 자료를 먼저 확인한다.

파일 수집은 파일에 포함된 범위다. 실제 화면의 전체 품목을 검증했다는 뜻이 아니다. 빈값과 0은 구분하며, 계약 JSON 총액은 전체 품목 금액 합계의 10원 미만 절사다. 기존 품목을 유지하여 총액이 달라지면 저장을 중단한다.

예전에 PDF 로 들어온 공고·계약은 진짜 키로 선 자료라 그대로 남는다. 그 위에 수집하면 기존 품목과 새 원천 행의 대응을 고르는 같은 검토를 탄다. 지난 PDF 비교가 남긴 `pdf:` 원천 행은 이번 수집에 없다고 지우자고 하지 않는다.

## 매핑 관리

필드 대응 편집에서 원천 경로와 변환을 바꾸거나, JSON 편집에서 표 경로·복합키·필드·코드 대응·전체 건수 선택자를 편집한다. 매핑 파일 불러오기/내보내기를 제공한다.

**편집본 저장 → 샘플로 검증 → 검증한 매핑 활성화** 순서로 적용한다. 변경한 모든 프로필에 샘플 검증이 필요하다. 이전 버전 또는 기본 매핑을 불러와 같은 절차로 복원할 수 있다. 활성화 자체는 기존 업무자료를 다시 쓰지 않는다. 수집 이력의 허용 필드 또는 원본 파일로 재검토한다. 이력에는 매핑 당시 허용했던 필드만 있으므로 새로 추가한 원천 필드는 원본 파일이 필요하다. 이력의 자료에는 메뉴 경로가 남지 않아 저장할 때 읽은 화면의 번호(`screen`)를 함께 적고, 재검토는 그 번호로 가린다 — 번호를 적기 전의 이력은 재검토하지 않고 원본 파일을 열라고 한다.

매핑은 선언형 데이터다. 임의 JavaScript/SQL이나 대상 DB 열을 실행·추가할 수 없다. 민감·내부 경로는 거부한다. 프로필 ID와 자료 종류, 그리고 받는 화면(`screen`)과 그 화면의 고유키(`identitySource`·`baseField`·`seqField`)는 기본 매핑의 것으로 고정한다 — 편집본이 바꾸면 저장·검증에서 거절한다. `screen` 을 적기 전에 저장한 매핑은 읽을 때 기본의 `screen` 을 채운다. 알 수 없는 코드는 추정 명칭으로 바꾸지 않고 미확정으로 남긴다.

## 접수

접수의 키는 나라장터의 접수번호(`ctrtDmndRcptNo`)·접수차수(`ctrtDmndRcptOrd`) 그대로다. 접두어를 달지 않는다(ADR-027). 접수는 **확장이나 JSON 으로 수집해야만 선다.**

스키마 17 에 있던 **PDF 접수 대응**(ERP 접수키와 PDF 대표접수키를 손으로 잇는 별칭)은 걷었다. 사람이 순서를 지켜야만 동작해 지키지 않으면 조용히 두 벌이 섰다. 판올림(스키마 18)은 `ERP:X` 를 `X` 로, 별칭으로 이어진 PDF 접수를 그 ERP 접수번호로 옮기고, PDF 에서만 온 접수는 지운다.

명시된 접수·공고 참조로만 연결한다. 사람의 확정·거절과 기존 링크를 보존한다. 같은 접수를 참조한 공고를 묶어도 대체 순서는 추정하지 않는다. 현행 후보가 여럿이면 **현행 확인 필요**로 표시한다. 계약 여러 건을 한 건으로 축약하지 않는다. 계약 품목 순번을 접수 품목 순번으로 간주하지 않는다.

## Chrome / Edge 확장

앱과 확장을 함께 업데이트한다. 확장 0.3.x 는 Native Messaging 프로토콜 2를 사용한다.

### 단일 exe로 추가하기

1. `계약목록.exe`를 계속 사용할 위치에 두고 정상 실행한다.
2. **나라장터 → 확장 준비**를 누른다. exe 안의 확장을 `%LOCALAPPDATA%\Pclm\extension`에 꺼내고 현재 사용자 Chrome/Edge Native Host를 이 exe에 연결한다. 관리자 권한·별도 다운로드·PowerShell 스크립트는 필요하지 않다.
3. **Edge 확장 관리 열기** 또는 **Chrome 확장 관리 열기**를 누른다. 브라우저는 명령줄로 받은 `chrome://`·`edge://` 주소를 막고 새 탭만 열기 때문에, 앱은 새 창을 띄워 그 주소창에 주소를 적고 Enter 를 누른다(그 창이 앞에 왔을 때만). 확장이 이미 붙어 있으면 확장에 맡겨(`openExtensions`) 연다. 넣지 못하면 주소를 클립보드에 복사해 두고 알린다 — 주소창에 붙여넣는다.
4. 브라우저에서 **개발자 모드 → 압축해제된 확장 프로그램을 로드합니다**를 누르고 앱에 표시된 확장 폴더를 선택한다. 두 브라우저 모두 사용한다면 각각 추가한다.
5. 나라장터 탭을 새로고침하고 확장을 연다. 업무 DB를 사용하려면 확장 **설정** 창의 **개발 DB 사용**은 끈다.

배포 파일은 exe 하나지만, 추가 후에는 브라우저가 읽는 확장 폴더를 유지해야 한다. 업데이트·이동은 손댈 것이 없다. 한 번 준비한 뒤로는 앱을 켤 때마다 확장 파일과 연결 경로를 지금 exe로 고치고(같으면 쓰지 않는다), 확장은 나라장터 화면을 열 때 호스트가 알려 준 판이 다르면 스스로 다시 불러온다. 그래도 옛 판이면(다른 폴더에서 로드한 확장 등) 설정의 확장 상태가 알려 준다 — 확장 관리에서 새로고침한다. 공개 키로 확장 ID를 고정하므로 Edge/Chrome 또는 설치 경로가 달라도 같은 ID를 쓴다. 과거 소스 폴더로 로드한 확장은 제거하고 위 폴더를 추가한다.

**준비 완료는 브라우저 설치 완료가 아니다.** 일반 Windows 브라우저에서 로컬 확장을 자동 강제 설치하지 않는다. 조직 정책으로 개발자 모드나 사용자 Native Host가 금지되어 있다면 관리자에게 문의한다. 공식 절차: [Edge 로컬 설치](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading), [Chrome 배포 제한](https://developer.chrome.com/docs/extensions/how-to/distribute/install-extensions).

업무 홈이 아닌 실행(`--home`·`--erp-dev`)에서는 사람의 브라우저 연결을 덮어쓰지 않도록 내장 확장 준비를 거부한다.

### 단축키와 설정 창

**Alt+Shift+S**(기본값)는 현재 나라장터 화면을 확인하고, 고를 충돌·대응하지 못한 품목·결과를 확인하지 못한 저장이 하나도 없을 때만 바로 저장한다. 하나라도 있으면 저장하지 않고 검토를 기다린다. 확인·저장은 팝업의 저장 버튼과 같은 검증(탭 origin, 최상위 프레임, 저장 직전 화면 재확인, 동시 요청 잠금, 미확인 저장 우선 해결)을 거친다. 결과는 페이지 수집기가 떠 있으면 거기에, 아니면 툴바 버튼 배지(✓ 저장, ! 검토 필요·오류)로 알리고, 검토가 필요하면 팝업을 열어 본다. 나라장터가 아닌 탭에서는 배지만 남긴다. 확장 팝업·수집기의 **설정**(또는 브라우저 확장 관리의 확장 옵션)에서 페이지 수집기를 항상 띄울지 툴바 버튼으로만 열지, **개발 DB 사용**, 단축키를 정한다. 단축키는 **단축키 바꾸기**가 여는 `chrome://extensions/shortcuts`(Edge는 `edge://extensions/shortcuts`)에서 바꾼다. 툴바 버튼으로만 열면 나라장터 화면을 관찰하지 않으며, 결과를 확인하지 못한 저장이 있으면 수집기를 띄우는 대신 툴바 버튼에 !가 붙는다. 이미 다른 확장이 같은 조합을 쓰면 브라우저가 단축키를 비워 두므로 설정 창에서 확인한다.

확장은 자료 자리를 보지도 옮기지도 않는다 — 작업자료를 옮기거나 바꾸는 일은 앱의 **설정 → 저장 위치**에서만 한다(ADR-032).

### 상시 연결(확장 0.8.0, ADR-035)

「마지막 연결」 은 확장이 나라장터 화면에서 인사한 흔적일 뿐이라, 확장이 지금 살아 있는지는 몰랐다. 0.8.0 의 확장은 서비스 워커가 뜰 때(그리고 브라우저 시작 때) `connectNative` 포트 하나를 열어 쥐고 있는다 — 포트가 열려 있는 동안 브라우저는 워커를 살려 두고, 그 포트로 띄워진 호스트는 포트가 닫힐 때까지 산다. 끊기면 1·2·5·15·60초로 물러서며 다시 잇고, 60초 넘게 버틴 포트가 끊기면 다시 1초부터 센다. **개발 DB 사용**을 바꾸면 지금 포트를 놓고 그쪽 호스트에 잇는다.

- 포트로는 `presence` 인사, 지금 보는 화면의 탭 보고·명령(아래), 수집 흐름의 사건(`event`)만 오간다. 수집·확인·저장·복구·내보내기 RPC 는 지금처럼 요청마다 `sendNativeMessage` 로 간다.
- 호스트는 인사를 받으면 홈의 `extension-live/<pid>.json` 에 브라우저·확장 판·프로세스 번호·시작 시각을 적고(마지막 연결도 함께 적는다), 포트가 닫히면 지운다. 브라우저·판은 마지막 연결과 같은 모양만 받는다.
- 이 인사는 **작업자료를 열기 전에** 받는다 — 브라우저만큼 사는 호스트가 DB 를 쥐거나 잠금을 잡지 않고, 쪽지가 없어도 인사는 된다.
- 붙을 때·끊길 때 홈의 `extension-log.txt` 에 한 줄씩 덧붙인다 — 시각 · 사건(`connected`·`disconnected`·`updated`, 그리고 확장이 알린 `error`·`recovered`) · 브라우저 · 확장 판 · 앞의 판(판 바뀜에만 — 오류면 그 코드), 탭으로 가른다. 읽는 쪽은 모르는 사건을 건너뛴다. 붙을 때 그 브라우저의 바로 앞 기록과 판이 다르면 `updated` 를 먼저 남긴다. 이레가 지난 줄과 500줄을 넘는 앞쪽은 쓸 때 스스로 버린다. Edge·Chrome 의 호스트가 함께 써도 파일을 홀로 열고 막히면 잠깐 기다려 줄이 섞이지 않는다. 쓰지 못해도 연결은 막지 않는다. 끊긴 까닭은 적지 않는다.
- 앱은 어느 화면에서든 2초마다 `extensionStatus` 를 읽어(바뀐 것이 없으면 다시 그리지 않는다) 그 프로세스가 **같은 시작 시각으로** 아직 돌 때만 「연결됨」 으로 센다. 끝난 프로세스의 파일은 거둔다. 같은 답에 오늘의 연결 기록이 실려, 사이드바의 나라장터·통로·Chrome 확장 상태가 한 번 읽은 것으로 같은 말을 한다. 열람 창도 읽기만 하므로 그대로 보인다.
- 실측: 끊겨도 다시 이어지고, 호스트 하나가 ~100MB 로 상주한다. 포트를 쥔 호스트가 exe 를 붙들어 **덮어쓰기는 실패하고 이름 바꾸기는 된다.**
- 그래서 새 판은 옛 exe 의 이름을 바꿔 비킨 뒤 놓는다. 이름은 `계약목록.old.exe` 또는 `계약목록.old-<숫자>.exe` 하나로 정한다. 호스트는 인사를 받은 뒤 3초마다 제 exe(개발 빌드면 `계약목록.dll` 도)의 자리·크기·쓴 때를 보고, 비켜졌거나 다른 파일이 섰으면 끊김을 적고 떠난다 — 확장이 물러서며 다시 붙으면 그 자리의 새 exe 가 뜨고, 나라장터 화면의 `hello` 판 비교로 확장도 새 판을 불러온다. 요청 하나만 받는 수집 호스트는 지켜보지 않는다. 창은 켜질 때 exe 옆과 홈의 옛 exe 를 지우고, 아직 쥐여 있으면 다음 번으로 미룬다.
- `publish.ps1` 은 붙들린 배포물 exe 를 출력 폴더 **밖**(`dist/계약목록.old-<시각>.exe`)으로 비키고 진행하며, 다음 배포 때 치운다. `run.ps1` 은 등록된 업무·개발 호스트가 창 빌드 출력(`src/Pclm.App/bin/…`)을 가리키면, 빌드 전에 그 폴더에서 붙들린 dll·`계약목록.exe` 만 같은 자리에서 `<이름>.old-<시각><확장자>` 로 비킨다(등록 스크립트의 `pclm-erp-dev.exe` 사본은 건드리지 않는다).

### 지금 보는 화면(ADR-036)

포트가 열린 동안 확장은 나라장터 탭마다 마지막으로 읽은 것(`reading`·`supported`·`unsupported`·`error`, 읽은 때, 머리 제목, 스냅샷)을 `tabs` 로 보고하고, 호스트는 그것을 `extension-live/<pid>.tabs.json` 에 바꿔치기로 쓴다. 창은 그 스냅샷마다 **창 안에서** inspect 하고 savepoint 위에서 면 뷰로 표기를 읽어 비춘다(같은 스냅샷·같은 dataVersion 이면 다시 하지 않는다). 창의 명령은 `extension-live/<pid>.cmd/` 에 놓이고 호스트가 포트로 넘긴다 — `focusTab`(그 탭·창을 앞으로), `read`(다시 읽기), `export`(그 탭의 수집기가 현재 화면 엑셀로 내보내기). 창의 가져오기는 확장의 저장과 같은 `ErpCapture.Save` 를 쪽지와 함께 부른다. 포트가 없으면 확장은 탭을 읽지도 보고하지도 않는다.

포트로 오가는 메시지(모두 `protocolVersion: 2`):

| 쪽 | 메시지 | 실은 것 |
|---|---|---|
| 확장 → 호스트 | `presence` | `{extensionVersion, browser}` — 인사. 이것을 받아야 아래를 받는다 |
| 확장 → 호스트 | `tabs` | `{front, frontAt, tabs:[{tabId, windowId, title, state, readAt, screen, snapshot?, screenRows?, message?}], settings?}` |
| 확장 → 호스트 | `event` | `{kind:"error", code}` · `{kind:"recovered"}` — 코드만, 자료는 없다 |
| 호스트 → 확장 | 탭 명령 | `{command:"focusTab"\|"read"\|"export", tabId}` |
| 호스트 → 확장 | 설정 명령 | `{command:"setPanelMode", mode:"always"\|"button"}` · `{command:"openShortcuts"}` · `{command:"openExtensions"}` |

- `screenRows:[{group, label, text, source}]` — 화면 그대로. 수집 규칙이 읽는 칸마다 화면의 이름표(aria-label → title → label → `[data-title]`, 없으면 같은 줄의 앞 `th`)와 보이는 글, 가장 가까운 앞의 구역 제목. 품목은 줄마다 `「순번 품명」 / 「수량단위 · 금액」` 원값이고 `source` 는 `table:<대상 표>:<몇째 줄>`. 지원 안 되는 화면은 내보내기의 화면 필드 앞 40줄(`source` 빈 글). 호스트는 글 넷의 줄인지, 400줄을 넘지 않는지만 본다. 창은 면 열마다 그 열을 채우는 자리(`Views.FaceReferences` 로 열 정의에서 끌어낸 것)를 이 줄과 이어 「화면 · 이름표」 와 화면 표기를 단다.
- `settings:{panelMode, shortcut, siteAccess}` — 수집기를 띄우는 방식(옵션 창과 같은 `panelMode`), 현재 화면 바로 저장의 단축키, 나라장터 사이트 접근. 바뀌면 다시 보고한다. 창의 「Chrome 확장 상태 · 설정」 이 보이고, 바꾸면 앞 탭의 브라우저(없으면 처음 붙은 것)에 설정 명령을 보낸다.
- `event` 의 코드 — `unconfirmed`(저장 결과 미확인) · `connection`(저장 대상에 연결 못 함) · `setup`(저장 대상 준비 필요) · `rejected`(저장 대상의 거절) · `response`(응답 모양이 다름). 화면 안내(번호를 못 찾음·화면이 바뀜)는 오류로 세지 않는다. 결과를 확인하지 못한 저장을 같은 요청으로 다시 보내 풀면 `recovered`. 뜻은 앱이 안다.

### 소스·개발 환경 등록

저장소의 `extension` 폴더를 직접 로드하는 개발자는 표시된 확장 ID와 빌드한 WPF exe를 지정한다. 이 경로도 현재 사용자 영역에만 등록한다.

```powershell
./scripts/register-erp-host.ps1 -ExtensionId '<확장 ID>' -ExePath '<배포 폴더의 실행 파일>'
```

개발 환경은 앱의 `--erp-dev`, 등록 스크립트의 `-Development`, 확장 설정 창의 **개발 DB 사용**을 함께 사용한다. 업무·개발은 홈으로 갈린다 — 개발 호스트와 `--erp-dev` 창은 홈이 `%LOCALAPPDATA%\Pclm.Erp.Dev` 인 것만 다르다. 미확인 저장 요청은 처음 선택한 호스트에 고정되어 환경을 바꿔도 다른 DB로 재전송되지 않는다.

호스트는 홈의 쪽지(`config.json`)를 읽기만 하고 쓰지도 판을 올리지도 않는다. 쪽지가 멀쩡하고, 가리키는 파일이 지금 판의 작업자료이고, 그 신원(`datasetId`)이 쪽지와 같을 때만 연다. 저장은 쓰기 잠금을 얻은 뒤 쪽지와 파일의 신원·역할을 **다시** 보고, 그 사이 앱이 작업자료를 바꿨으면 거절한다 — 저장은 바꾸기 전 자료에 들어가거나 거절될 뿐이다(ADR-032). 작업자료를 옮기면 신원이 이어져 열린 검토가 새 자리로 이어지고, 다른 작업자료로 바꾸면 옛 검토의 저장은 거절된다. `--home` 으로 띄운 앱은 업무 홈의 쪽지를 건드리지 않는다.

### 실제 ERP 화면 검증이 필요한 부분

공개 물품공고 기본정보 7개만 읽는 확장 보조 경로는 제거했다. 저장 매핑이 맞지 않으면 DB 저장을 차단하고 엑셀 내보내기를 안내한다. 기존 매핑과 저장 자료의 호환성을 위해 서버의 과거 프로필 정의는 유지하지만 확장의 수집 후보에서는 제외한다. 접수·공고 A/B·계약의 전체 표 수집은 선언형 프로필과 WebSquare DataList 읽기를 사용하며, 실제 로그인 업무 화면의 API·표 범위는 현장 검증이 필요하다.

화면은 **문서 번호 하나로** 가린다. 매핑의 번호·차수(접수 `ctrtDmndRcptNo`·`ctrtDmndRcptOrd`, 공고 `bidPbancNo`·`bidPbancOrd` 또는 `bidPbancText`, 계약 `ctrtNoOrd`)를 읽을 수 있는 매핑이 후보다. 계약 화면은 공고·접수 번호를, 공고 화면은 접수 번호를 참조로 함께 싣기 때문에 후보가 여럿이면 가장 아랫단 문서(계약 → 공고 → 접수)를 고른다. 표·제목은 있으면 담고 없거나 비면 수집하지 않은 것으로 두어 기존 값을 건드리지 않는다. 덜 불러온 표에서 빠진 행은 「행 삭제」 충돌로 나와 사람이 고른다 — 전체 건수를 따로 세어 막지 않는다(`totalSelector`는 읽지 않는다). 화면 값은 컴포넌트 원값을 먼저 읽고, 보이는 칸에 없으면 같은 자료에 묶인 숨은 칸을 쓴다. 부가 필드가 둘 이상의 값으로 관찰되면 그 필드만 수집하지 않는다. 막는 것은 로딩 중, 번호·차수의 형식 오류나 값 충돌, 같은 단의 문서가 둘, 품목 행 키의 누락·중복뿐이다.

### 현재 화면 엑셀 내보내기

나라장터의 업무 화면에서 확장 팝업이나 페이지 수집기의 **현재 화면 엑셀로 내보내기**를 누른다. 확장과 나라장터 탭을 새로고침하면 새 버튼이 표시된다. 이 기능은 Native Host·앱·DB 연결·활성 매핑·전체 건수 선택자 없이 동작한다.

- `화면 필드`: 값이 있는 입력·선택·WebSquare 텍스트의 항목명, 표시값, 원본 ID, 참조 필드.
- 표별 시트: 화면에 표시된 WebSquare 표의 DataList에 현재 로딩된 행. 열은 원천 필드 ID를 사용한다. 동일 DataList의 중복 표현은 한 번만 내보내며 동일 값을 가진 실제 행은 유지한다. ID와 머리글이 있는 일반 HTML 표도 지원한다.
- `수집 정보`: 화면명, query/hash를 제외한 출처 주소, 수집 시각, 시트별 원본 ID와 행 수, 읽지 못한 표.

빈 열, 숨김 입력, 비밀번호·세션·계좌번호·주민번호로 식별되는 필드, 내부 행 상태값은 제외한다. 표의 중첩 객체는 단일 값만 경로로 펼치고 배열은 제외한다. 병합 셀이 있는 일반 HTML 표는 제외 사유를 기록한다. 셀은 문자열로 저장하여 선행 0과 긴 번호를 보존하고 수식처럼 보이는 원문을 실행하지 않는다.

현재 최상위 화면에서 관찰할 수 있는 자료의 스냅샷이다. 다른 페이지·미개방 탭·iframe을 순회하거나 서버를 추가 조회하지 않으며 전체 품목 수를 보장하지 않는다. 최대 200시트·50만 셀·32 MiB이며 Excel 셀 길이·행·열 제한을 넘으면 잘라 저장하지 않고 오류를 표시한다. 자료는 확장에서 `.xlsx`로 생성되어 브라우저 다운로드 설정에 따라 저장된다.

## 데이터와 검증

새 원천/행키/업체 자료는 제출·취합과 내보내기에 포함한다. 활성 매핑과 수집 재전송 영수증은 로컬 설정이므로 취합하지 않는다. 새 읽기 전용 뷰는 [데이터셋 규약](../dataset-contract.md)을 참고한다.

회귀 검증은 기존 `ErpCaptureTests`, `MergeTests`, `ErpExtension.test.tsx`, `SettingsPanel.test.tsx`를 확장했다. 저장 선택, 동시 변경, 재전송, 허용 필드, 복합키, 취합의 부모 선택을 확인한다. 기존 공고 전용 통신 검증은 공통 프로토콜 검증으로 대체했다.

```powershell
# 개인 JSON 코퍼스는 저장소에 넣지 않는다.
$env:PCLM_JSON_CORPUS = '<로컬 json.zip>'
dotnet test tests/Pclm.Core.Tests --no-restore
npm test
npm run build
dotnet build src/Pclm.App --no-restore
```
