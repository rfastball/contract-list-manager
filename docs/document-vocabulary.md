# 문서 만들기 어휘

확장의 「문서 만들기」 사이드 패널(ADR-045 · ADR-047)이 서식의 누름틀 이름과 계약목록의 값을 잇는 표다. 사용자는
바꾸지 않고, 서식을 이 이름으로 쓴다.

- 서식의 칸 이름은 **통합 뷰의 열 이름**이다. 통합 뷰는 exe 에 실린 보기 구성
  ([`presets/builtin-views.json`](../crates/pclm-core/src/storage/presets/builtin-views.json))의 「문서 서식」 —
  호스트 `document {op:"read"}` 가 읽을 때마다 작업자료의 「문서 서식」 줄의 정의(없으면 이 파일의 것)를 셈해 열 이름 → 글의
  한 줄로 싣는다. 깔린 `u_*` 는 읽지 않는다. 창의 「문서 서식」 은 앱이 열 때마다 이 정의로 맞추되, 사람이 고쳐 저장하면
  그 정의가 문서를 채운다(ADR-050 · 052). 아래 표는 exe 의 정의다 — 사람이 더한 열은 표에 없어도 엔진이 건의 값에서
  같은 이름을 찾는다.
- 열의 다른 이름(옛 서식의 칸 이름)과 내 정보는 [`crates/pclm-doc-engine/vocabulary.json`](../crates/pclm-doc-engine/vocabulary.json) 에 있다. 엔진
  (`include_str!`)이 두 파일을 읽고, 패널은 엔진의 `vocabulary` 요청으로 같은 것을 받는다. 아래 표는
  `cargo run -p pclm-doc-engine --example vocabulary_doc` 이 짓는다 — 손으로 고치지 않는다(시험이 어긋남을 잡는다).
- 이름이 겹치면 통합 뷰의 열이 먼저다. 그래서 `담당자` · `담당부서` 는 내 정보가 아니라 공고의 수요기관 쪽
  담당자다(`공고담당자` 와 다른 사람 — [자료 계약](dataset-contract.md)).
- 내 정보(부서 · 이름 · 연락처 · 팩스)는 패널의 「설정」 에서 한 번 적는다. 동봉 공고서(「물품 구매입찰 공고」)의 「① 계약담당자」
  줄은 `계약담당자` · `계약담당 전화번호` · `계약담당 팩스번호`(내 이름 · 연락처 · 팩스의 다른 이름)로 내 정보를 채우고, 「② 수요기관
  연락처」 줄은 통합 뷰의 `수요기관` · `담당부서` · `담당자` · `담당자 전화번호` 다. 그 서식처럼 내 정보 칸을(다른 이름으로라도) 쓰는
  서식을 고르면, 패널은 내 이름이 `공고담당자` 에 들어 있지 않거나 내 연락처가 `공고담당 전화번호` 와 숫자로 다를 때 다르다는
  것만 보인다(어느 쪽이든 비었으면 견주지 않고, 저장 · 복사는 막지 않는다). 부서 · 팩스는 견줄 열이 없다.
- 공고서 맨 위 날짜는 게시 전에 쓰는 것이라 게시일이 아니라 쓰는 날의 연 · 월(`오늘_년월`, `2026. 9.`)이다.
- 이름을 견줄 때 빈칸·밑줄·가운뎃점·붙임표는 보지 않는다(`계약 금액` = `계약금액`).
- 여기 없는 이름의 누름틀, 값이 없는 누름틀은 【확인 필요】로 남는다. 입력 칸은 두지 않는다.
- 확장에 실린 서식 셋의 칸이 모두 이 표에 있는지 시험(`tests/vocabulary.rs`)이 대조한다 — 통합 뷰의 열 이름을
  바꾸면 거기서 붉어진다.

## 값의 꼴

조사 자동 선택은 시스템 토큰 `@조사:대상필드:은/는`으로 명시한다(ADR-054). TXT에서는
`‘{{수요기관}}’{{@조사:수요기관:은/는}}`, HWPX에서는 `수요기관` 누름틀과 `@조사:수요기관:은/는` 누름틀을 따로 둔다.
조사 토큰은 대상 값이 아니라 조사만 출력한다. 대상은 아래 표의 이름·별칭 또는 사용자가 더한 열 이름이다.
지원 조사쌍은 `은/는`, `이/가`, `을/를`, `과/와`, `으로/로`다. 한글 끝음절만 판정하고 숫자·영문·기호로 끝나거나
값이 없으면 병기를 남겨 확인을 요청한다. 값 바깥의 따옴표·괄호는 판정과 무관하다. 잘못된 토큰이나 없는 대상 이름은
생성을 막는다. `@`로 시작하는 이름은 시스템 예약어이며 일반 필드로 사용하지 않는다.

- 값은 「문서 서식」 이 낸 글 그대로다 — 엔진은 바꾸거나 더하지 않는다(ADR-051). 창에서 `u_문서 서식` 으로 보는 글이
  문서에 찍히고 파일 이름에 들어간다. 계약목록에서 고친 값(덮개)도 면 뷰가 이미 씌워 낸다. 면 뷰 · 엑셀의 값은 면 뷰의
  표기([자료 계약](dataset-contract.md) 「공통 표기」) 그대로다.
- 문서에 찍힐 꼴은 뷰가 흐름식 「서식」 의 엑셀 표시 형식 코드로 짓는다(ADR-053, [user-views.md](user-views.md) §13):
  - 금액(`사업예산` · `추정가격` · `계약금액` · `계약보증금`)은 `#,##0원` — `30400000` → `30,400,000원`(원 단위로 반올림).
    서식에는 「원」을 쓰지 않는다(「금」은 서식에 쓴다). 숫자로 읽히지 않는 글은 빈 글이다.
  - 일시 열(`게시일시` · `입찰개시일시` · `입찰마감일시` · `개찰일시` · `등록마감일시`)은 `yyyy. m. d. hh:mm` —
    `2026/09/14 10:00:00` → `2026. 9. 14. 10:00`(초는 찍지 않고, 시각이 없으면 `00:00`). `게시일` · `계약보증금납부기한` 은
    `yyyy. m. d.` 이다. 날짜로 읽히지 않는 글은 빈 글이다. `납품기한` 은 SQL 열이 공문서 표기(`공문서날짜`)로 지어,
    날짜가 아닌 글(`계약 후 90일 이내`)은 그대로다.
  - `계약금액_한글` · `추정가격_한글` 은 `[DBNum4]` — 면 뷰의 금액을 한글로(앱 함수 `한글금액`, 「일」을 살린다:
    114,500 → 일십일만사천오백). `공고일시_년월일` 은 게시일시를 `yyyy년 m월 d일`, `오늘_년월일` · `오늘_년월` 은 호스트가
    읽는 날(시작 데이터 `오늘`, SQLite `date('now', 'localtime')`)을 `yyyy년 m월 d일` · `yyyy. m.` 로 짓는다.
- 내 정보는 패널이 적힌 그대로 더한다.
- 빈 글은 값이 없는 것이다.
- 공고 탭에서는 통합 뷰의 공고 자리가 **그 탭의 공고**다 — 재공고 · 취소공고로 번호가 바뀌어도 탭이 연 공고의 값과
  품목이다. 접수 · 계약 탭은 그 사슬의 현행 공고를 쓴다.
- 한 공고에 계약이 여럿이면 계약마다 다른 칸은 비운다(답의 `rows` 가 계약 수다) — 짐작해 고르지 않는다.
- 같은 공고의 옛 차수 탭이면 값은 최신 차수의 것이고, 패널이 그렇다고 알린다(답의 `older`).
