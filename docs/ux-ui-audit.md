# UI 재설계 audit → polish 기록

## 열 만들기 시나리오 재작성 (2026-10-08 후속)

사용자 피드백에 따라 “빈 정의 양식 작성”에서 “자료를 보며 필요한 열 만들기”로 흐름을 바꿨다. 아래 최초 audit 점수는 이전 구현의 기록이며 이번 UX 개선의 평가 점수로 재사용하지 않는다.

- 입력열: 직접 기록할 목적 안내 → 이름·입력 방식 → 기존 열과 나란한 새 열 미리보기 → 입력 연습 → 저장. 연습 값은 저장하지 않는다. 기존 열의 이름을 바꿀 때는 기존 입력값을 미리보기에 유지한다.
- 가공열: 실제 문서·차수와 품목 값을 보며 필드 선택 → 모든 품목 모으기/특정 품목/개수 선택 → 자동 계산 → 저장. 품명 모음·품명과 번호·품명 수 예시로 시작할 수 있고, 서식 문법은 고급에서만 편집한다.
- 원본은 미리보기와 같은 최신 부모 5건이다. 원본 조회는 문서당 최대 100개 품목으로 제한하며 UI는 처음 3개 값을 나란히 읽는다. 계산은 해당 문서의 품목 전체를 사용한다. 차수 9→10에서 문자열 비교로 최신 문서가 엇갈리던 문제를 숫자 비교로 수정했다.
- audit 후 polish: 공고명·요청명을 놓치던 미리보기 제목 탐색을 대상별 매핑으로 수정했고, 좁은 창에서는 열 목록을 숨겨 작업 폭을 확보했다. 입력열에는 기존 마지막 열도 함께 보여 새 열의 위치를 명확히 했다.
- 검증: 기존 화면 owner 58개 우선 통과, 전체 프런트엔드 201개/21.50초·코어 475개/46초 통과. 이전 계산 응답의 지연 도착, 기본 자동 서식, 실패 초안, 연습값 미저장, 읽기 전용을 기존 시나리오에 확장했다. 이번 케이스·파일·외부 자원·의존성 증가 0, 실행시간 증감은 동일 조건 기준이 없어 미측정.
- TypeScript/Vite 배포 빌드 통과. 번들 detector는 변경 컴포넌트·CSS에 실행, 종료 0·출력된 지적 없음. 코어 테스트 빌드에는 이번 변경 밖 `Erp/Mapping.cs`의 기존 CS8619 경고가 있었다.
- 브라우저 예시 자료로 넓은 창과 760px 창의 원본 선택·자동 계산, 가공열 저장, 입력열 연습, 저장 영역 접근을 확인했다. 가로 넘침·확인한 콘솔 오류 없음. 실제 사용자 DB와 Windows 실행 중인 앱은 변경하지 않았다. 화면: `artifacts/ui-redesign/columns-source.jpg`, `artifacts/ui-redesign/columns-input.jpg`.

## 구현 일관성 판정

통과. 자료 종류 탐색과 수집 연결 상태를 분리하고, 표 선택에 따라 해당 작업만 나타나도록 했다. 열 정의는 설정에서 전용 작업 영역으로 이동했다. 기존 글꼴·테마 변수·Modal을 재사용했고 UI 라이브러리나 실행 의존성을 추가하지 않았다.

번들 detector를 변경한 화면·스타일에 실행했다. 종료 코드 0, 출력된 지적 없음. 이는 정적 도구 결과이며 시각 품질이나 WCAG 준수 인증을 뜻하지 않는다.

## 발견 항목과 polish 처리

P0 0건, P1 2건, P2 9건, P3 1건. 각 항목은 국소 결함으로 분류하여 수정했다.

| 심각도 | 위치 | 사용자 영향 | 처리 |
|---|---|---|---|
| P1 | Grid 셀 pointerdown | 다른 셀을 누를 때 편집값 저장이 건너뛰어질 가능성 | 편집 중 native blur를 보존 |
| P1 | navigation.css 신규 수집 숫자 | 작은 글자 대비가 4.5:1 미만 | primary 토큰으로 변경, WCAG 1.4.3 대비 기준 확인 |
| P2 | Grid 행 선택 키 입력 | 이전 셀이 의도치 않게 편집될 수 있음 | 행 선택 중 문자·삭제·편집 키 차단 |
| P2 | App 저장 후 새로 읽기 | 저장 완료 후 조회 실패를 저장 실패로 오인·재실행 | 커밋 실패와 조회 실패를 분리해 안내 |
| P2 | BatchOperations 연결 집계 | 공고 재구성으로 옮겨진 연결을 삭제로 과대 집계 | 계약·접수의 안정된 식별자로 비교 |
| P2 | 좁은 sidebar 순서 | 화면 순서와 키보드 이동 불일치 | CSS order와 DOM 순서 일치 |
| P2 | App 열 관리 진입 | 이전 자료 화면이 계속 선택된 것처럼 표시 | 열 관리 동안 자료 탭 선택 표시 해제 |
| P2 | ColumnManager 성공 알림 | 좁은 창에서 저장·제거 결과가 숨겨짐 | 항상 보이는 헤더에 상태 표시 |
| P2 | ColumnManager 상세 종료 | 숨겨진 제목으로 초점 이동 | 열 목록 검색으로 복귀 |
| P2 | ColumnManager 초기 열 요청 | 늦은 열 정의 응답 시 원하는 상세를 놓침 | 사용자 탐색 전 한 번만 지연된 요청 해소 |
| P2 | 열 관리 저장 오류 | 동일 오류가 토스트와 상세에서 중복 낭독 | 상세가 오류 표시를 소유 |
| P3 | ColumnManager 목록 이름 | 열 이름·대상·종류가 붙어서 읽힘 | 구분된 접근성 이름 지정 |

발견 항목은 `$impeccable polish`에서 모두 처리했다. 공통 원인은 기존 단일 셀·설정창 흐름을 새 선택 상태와 별도 작업 영역으로 옮길 때의 상태 소유권이었다. 데이터 변경과 화면 새로 읽기의 성공 여부도 분리했다.

## 검증 증거

- 프런트엔드 전체 201개 / 20.06초 통과. 이후 행 선택 테스트의 시작 셀을 편집 가능한 셀로 강화하고 해당 Grid 27개 / 6.94초 재확인.
- 코어 전체 475개 / 42초 통과. 일괄 편집 검증·전체 롤백, 삭제 중복 제거·영향 변경 거절·연결 재구성, 스냅샷 엑셀 반출을 기존 소유 테스트에 추가했다.
- 테스트 비용: 화면 +5, 코어 +5. 새 테스트 파일·외부 서비스·CI 경로·의존성 추가 0, coverage 기준 변경 없음. 기존 UI 동선 증거는 새 동선으로 교체했다. 동일 조건의 변경 전 측정값이 없어 실행시간 증감은 미측정.
- TypeScript와 Vite 배포 빌드 통과. JS 356.51 kB(압축 108.39 kB), CSS 83.91 kB(압축 14.58 kB). 기존 Pretendard 폰트 5.4 MB 유지.
- WPF 별도 출력 빌드 통과, 경고·오류 0. 실행 중인 사용자 앱과 파일 잠금 충돌을 피하기 위해 `artifacts/ui-redesign-build`에 생성했다.
- 브라우저 예시 자료에서 Shift 행 선택, 열 관리 왕복 시 선택 유지, 초안 이동 확인, 좁은 창 초점 복귀·가로 넘침 없음, 3셀 일괄 검토→저장 결과를 확인했다. 확인한 콘솔 오류 0.
- 검증 화면: `artifacts/ui-redesign/table.jpg`, `artifacts/ui-redesign/columns.jpg`. 실제 사용자 DB의 변경·삭제는 실행하지 않았다.
- 실제 Windows WebView2 앱 재시작, 파일 저장 대화상자, 물리 터치, 스크린리더, 어두운 테마 렌더·150% 확대는 이번 브라우저 검증에 포함되지 않았다. 좁은 viewport 검증은 터치 제스처 검증을 대체하지 않는다.

## 유지할 원칙

행 삭제와 셀 비우기는 다른 동작으로 유지한다. 통합에서 삭제할 자료 종류는 직접 선택하고 실제 문서 중복을 제거한다. 일괄 변경은 현재 값의 변경 여부까지 검증한 뒤 하나의 트랜잭션으로 저장한다. 열 정의는 명시적으로 저장하며 실패·이동 취소 시 초안을 유지한다. 이 경계의 회귀 검증은 기존 Grid·App·SettingsPanel·ReadOnly 및 코어 테스트가 계속 소유한다.
