## 상세 문제

### 1. [P1] 좁은 창과 글자 150%에서 표가 완전히 사라진다

**분류:** 창 크기·글자 확대 대응 · **증거:** 브라우저 실행 및 DOM 측정

**위치:** `frontend/css/navigation.css:34`, `frontend/css/app.css:23`, `frontend/css/app.css:150`, `frontend/css/app.css:164`, `frontend/css/app.css:1079`, `frontend/css/grid-work.css:3`, `frontend/css/grid-work.css:43`.

**재현:** 창을 760 × 800으로 맞추고 설정의 화면 표시에서 글자 크기를 150%로 바꾼 뒤 계약 목록을 연다. 검색·선택 작업 띠는 보이지만 표 머리글과 자료 행은 보이지 않는다.

측정한 높이는 사이드바 **360px**, 작업 영역 **407.4286px**, 선택 작업 띠 **72px**, `.grid-board` **0px**이었다. 표 본문의 시작 위치는 y=722.91이며 내부 `scrollHeight`는 2398px이어서 자료가 없는 상태와 구별된다. 같은 760 × 800에서 글자 100%로 바꾸면 사이드바는 336.357px, 표 본문은 104.321px로, 약 1–2행 정도의 공간이 남았다.

고정된 `100dvh` 안에서 좁은 창의 사이드바가 최대 `45dvh`를 쓰고, 작업 영역의 머리·보기 선택·검색·선택 작업이 남은 높이를 사용한다. 검색은 별도 줄로 바뀌고 글자 확대에 따라 작업 띠도 커진다. 표 감싸개는 `min-height: 0`, 본문은 최소 유효 높이가 없는 `flex: 1; overflow: auto`여서 마지막 자료 영역이 0까지 줄어든다.

**사용자 영향:** 지원하는 글자 확대 설정에서 목록을 읽거나 셀을 선택하는 핵심 작업을 수행할 수 없다. 표 영역 내부 스크롤만으로는 높이 0을 복구할 수 없다.

**수정 방향:** 좁은 창의 탐색을 접거나 압축해 자료 공간을 우선 확보한다. 선택 전 안내와 도구 모음의 상시 높이를 줄이고, 자료 본문의 최소 사용 높이를 정한다. 전체 최소 높이가 창보다 커질 때는 작업 영역 바깥의 세로 스크롤로 모든 조작부와 자료에 접근할 수 있게 한다. 표에 최소 높이만 추가하여 다른 영역이 잘리게 만드는 수정은 피한다.

**참고 기준:** WCAG 1.4.4 글자 크기 조정, 1.4.10 재배치의 취지와 관련된다. 이번 앱 150% 시험만으로 해당 기준의 전체 적합 여부를 판정하지 않는다.

**권장 명령:** `$impeccable adapt`.

### 2. [P1] 표의 현재 칸과 편집 입력이 접근성 트리에 충분히 전달되지 않는다

**분류:** 접근성 · **증거:** 브라우저 DOM 및 소스 확인, 실제 낭독기 미검증

**위치:** `frontend/src/Grid.tsx:562`, `frontend/src/Grid.tsx:763`, `frontend/src/Grid.tsx:826`, `frontend/src/Grid.tsx:844`. 비교할 기존 구현은 `frontend/src/Outline.tsx:231`이다.

**재현:** 계약 표의 첫 자료 칸을 선택한 뒤 방향키로 다른 칸으로 이동한다. DOM 초점은 일반 `div.grid-board`에 남고 현재 칸은 `td.cur` 클래스만 바뀐다. 편집 가능한 칸에서 F2로 편집하면 생성되는 input/select에는 열 이름이나 행 식별자를 연결한 접근 가능한 이름이 없다.

표 감싸개에는 `role="grid"`나 `aria-activedescendant`가 없고, 현재 칸에도 현재 위치·선택 상태를 전달할 속성이 없다. 일반 HTML 표 자체의 의미는 남아 있지만, 별도 키보드 커서가 어느 칸을 가리키는지는 연결되지 않는다. 하단의 행·열 안내 역시 현재 칸과 연결된 설명이나 실시간 알림이 아니다.

**사용자 영향:** 화면의 테두리로는 위치를 알 수 있지만 보조 기술에는 동일한 정보가 전달되지 않는다. 편집에 들어갔을 때 어느 행의 어떤 값을 바꾸는지 확인하기 어렵다. 실제 NVDA 발화 결과를 측정했다는 뜻은 아니다.

**수정 방향:** 이미 구조 보기에서 사용하는 현재 칸 연결 방식을 참고해 표의 키보드 커서와 접근성 트리를 연결한다. 선택한 구현 방식에 맞는 행·열·현재 칸 의미를 제공하고, 편집 input/select에 열 이름과 필요한 행 식별자를 연결한다. 시각적 커서·키보드 위치·보조 기술 위치가 같은 자료를 가리키게 한다.

**참고 기준:** WCAG 1.3.1 정보와 관계, [4.1.2 이름·역할·값](https://w3c.github.io/wcag/understanding/name-role-value.html). 소스의 누락을 확인한 것이며 낭독기 전체 동작에 대한 인증 결과는 아니다.

**권장 명령:** `$impeccable harden`.

### 3. [P2] 표의 Tab·Shift+Tab이 바깥 조작부로 이동하지 않는다

**분류:** 접근성 · **증거:** 브라우저 키보드 실행 및 소스 확인

**위치:** `frontend/src/Grid.tsx:459`, `frontend/src/Grid.tsx:474`, `frontend/src/Grid.tsx:495`, `frontend/src/Grid.tsx:506`, `frontend/src/useFindShortcut.ts:13`.

**재현:** 1280 × 800의 계약 표에서 첫 자료 칸을 클릭하고 Shift+Tab을 누른다. `document.activeElement`는 `.grid-board`에 남는다. 이어서 Escape, Shift+Tab을 눌러도 표에 남는다.

Tab·Shift+Tab은 기본 초점 이동을 막고 셀 커서만 옮긴다. Escape는 선택·안내를 정리하며 표 바깥으로 초점을 옮기지 않는다. 반면 **Ctrl+F로 검색 입력에 이동하는 우회 경로는 있다.** 따라서 키보드로 탈출이 불가능하다고 판정하지 않는다.

**사용자 영향:** 사용자가 표에서 검색·열 관리·다른 작업으로 돌아가기 위해 일반적인 Tab 규칙을 사용할 수 없다. 셀 이동과 조작부 간 초점 이동을 구분하기 어렵다.

**수정 방향:** 보기 상태에서 Tab을 표 바깥 이동으로 사용할지, 셀 편집 종료와 함께 이동할지 명확한 규칙을 정한다. 셀 간 이동을 Tab으로 유지한다면 표의 경계·Escape 등에서 조작부로 복귀하는 동작과 가까운 안내를 제공한다. 첫 칸과 마지막 칸, 보기와 편집 상태를 모두 확인한다.

**참고 기준:** [WCAG 2.1.2 키보드 함정 없음](https://w3c.github.io/wcag/understanding/no-keyboard-trap.html)은 비표준 탈출 방법이 필요할 때 그 방법을 사용자에게 알려야 한다고 설명한다. Ctrl+F 안내와 우회 경로가 있으므로 이번 결과만으로 완전한 키보드 함정 위반이라고 단정하지 않는다.

**권장 명령:** `$impeccable harden`, 동작 안내는 `$impeccable clarify`.

### 4. [P2] 비었거나 해석할 수 없는 흐름식 원문은 미저장 변경으로 추적되지 않는다

**분류:** 구현 일관성·초안 보호 · **증거:** 소스만 확인, 실행 재현하지 않음

**위치:** `frontend/src/columns/ColumnFlow.tsx:208`, `frontend/src/columns/ColumnFlow.tsx:289`, `frontend/src/columns/ColumnFlow.tsx:301`, `frontend/src/ColumnManager.tsx:116`, `frontend/src/ColumnManager.tsx:137`, `frontend/src/views/UserViews.tsx:90`, `frontend/src/views/UserViews.tsx:112`, `frontend/src/views/UserViews.tsx:318`.

**소스에서 도출한 재현 경로:** 저장된 가공열을 열고 흐름식 탭의 내용을 전부 지우거나 해석할 수 없는 원문으로 바꾼 뒤, 닫기·목록 이동 또는 다른 편집 탭을 선택한다. 다른 정상 변경이 없는 조건에서 원문이 미저장 초안에 포함되지 않아 확인 없이 버려질 수 있다.

`FlowCode`는 원문을 컴포넌트 내부 `text`에 보관한다. 빈 원문과 구문 오류는 부모의 `onFlow`를 호출하지 않으므로 저장 대상 식은 이전 값에 남는다. 열 관리와 내 보기의 dirty 판단은 부모의 직렬화한 draft만 비교한다. 화면에 마지막으로 읽힌 식을 설명하는 문구와 저장 방지는 있지만, 원문을 보호하는 상태는 없다. 탭을 떠나 `FlowCode`가 제거되면 원문과 오류 상태도 사라진다.

**사용자 영향:** 아직 완성하지 못한 식을 작성하다가 이동하면 작업한 원문을 잃을 수 있다. 저장 대상은 이전 식이어서 화면의 저장 상태가 사용자가 실제로 편집한 원문 상태를 충분히 설명하지 못한다.

**검증 제한:** 브라우저에서는 기존 공개 모의 보기의 이름 있는 흐름식 편집기와 식, 「저장됨」 상태까지만 확인했다. 기존 식을 전체 선택·삭제하고 이동하는 실행 검증은 **자동 승인 검토가 앱 상태 손실 위험을 이유로 거부했다. 해당 조작은 실행되지 않았으며 다시 시도하지 않았다.** 공개 모의 보기는 유지했다. 이 항목을 실행 재현 완료로 읽어서는 안 된다.

**수정 방향:** 원문 초안과 마지막 유효 식을 함께 유지하고 원문 변경도 dirty 판단에 포함한다. 잘못된 원문은 저장할 수 없더라도 계속 편집하거나 명시적으로 버릴 수 있어야 한다. 탭 이동·열 닫기·작업 영역 이동 모두 같은 보호 규칙을 적용한다.

**참고 기준:** 미저장 변경 확인이라는 `PRODUCT.md`·`DESIGN.md`의 제품 동작 규약과 관련된다. 별도 WCAG 위반으로 계산하지 않았다.

**권장 명령:** `$impeccable harden`.

### 5. [P2] 대시보드의 「자료 확인 필요」 사유가 title에만 있다

**분류:** 접근성·정보 접근 · **증거:** 브라우저 DOM 및 소스 확인

**위치:** `frontend/src/Dashboard.tsx:100`, `frontend/css/dashboard.css:43`.

**확인 경로:** 진행 단계 결과 중 「자료 확인 필요 n」이 있는 행을 키보드로 탐색한다. 브라우저에서 「자료 확인 필요 2」는 `tabIndex: -1`인 span이고, title에 「연결된 접수 문서가 DB에 없습니다.」「계약에 적힌 공고 문서가 DB에 없습니다.」가 들어 있음을 확인했다. 소스도 실제 사유를 `title={row.issues.join("\n")}`에만 둔다. 해당 사유를 의도적으로 펼칠 수 있는 단추나 disclosure는 없다.

**사용자 영향:** 마우스 툴팁을 띄우기 어려운 키보드 사용자는 무엇을 확인해야 하는지 직접 열어 읽기 어렵다. 일부 보조 기술이 title을 읽을 가능성과 별개로, 누구나 사용할 수 있는 사유 열기 동작이 빠져 있다.

**수정 방향:** 「자료 확인 필요 n」을 펼침 단추나 details/summary로 만들고 실제 `row.issues` 목록을 본문에 제공한다. 열기·닫기 상태와 초점을 연결하고, 사유를 보고 해당 문서로 이동할 수 있도록 현재 문서 열기 동작과의 관계를 명확히 한다.

**참고 기준:** WCAG 2.1.1 키보드 접근의 취지와 관련된다. title의 실제 낭독 여부는 시험하지 않았다.

**권장 명령:** `$impeccable harden`, 문구와 사유 구조는 `$impeccable clarify`.

## 반복되는 원인과 유지할 강점

이번 문제는 세 패턴으로 모인다. 첫째, 고정 높이 작업 화면에서 조작부의 높이는 보장하지만 자료 본문의 최소 사용 공간과 바깥 스크롤 복구 경로는 보장하지 않는다. 둘째, 시각적 상태는 구현했지만 표 커서·입력 이름·확인 사유를 키보드와 보조 기술에 같은 수준으로 전달하지 못한다. 셋째, 저장 가능한 데이터 상태와 사용자가 작성 중인 원문 상태를 동일하게 취급해 미완성 초안이 보호 밖에 놓인다.

다음 강점은 수정 시 유지할 가치가 있다.

- 조달 단계·최신 문서·납품기한의 의미가 구체적이며, 계약 체결과 납품 완료를 혼동하지 않도록 제품 규약이 있다.
- 수집 연결 상태와 자료 탐색이 구분되어 있고, 색 외에도 라벨·굵기·테두리로 상태를 전달한다. 확인한 기본 대시보드의 밝게·어둡게 화면은 읽을 수 있었다.
- 구조 보기는 현재 칸을 `aria-activedescendant`로 연결하고 방향키·Space·Enter를 제공한다. 표 개선에 참고할 내부 사례다.
- 공유 Modal은 native dialog로 배경 조작을 막고 초기 초점·Escape 닫기·기존 조작부 복귀를 처리한다.
- 변경·삭제 전 검토와 영향 확인, 원래 값 복원이라는 기존 구조가 있다. 이번 감사에서 실제 DB의 파괴 작업을 실행해 검증한 것은 아니다.
- 빈 결과의 조건 초기화, 불러오기·계산 오류의 재시도, 읽기 전용 상태가 주요 작업공간에 마련되어 있다.
- CodeMirror는 흐름식·SQL 탭에서 지연 로딩하며 기존 테마·글꼴 토큰을 따른다.

## 권장 진행 순서와 남은 검증

1. **P1 — `$impeccable adapt`:** 좁은 창·글자 확대에서 자료 본문이 사라지는 높이 배분과 스크롤 복구 경로를 고친다.
2. **P1/P2 — `$impeccable harden`:** 표의 현재 칸·입력 이름·Tab 복귀 규칙, 흐름식 원문 초안 보호, 확인 사유의 키보드 공개를 보완한다.
3. **P2 — `$impeccable clarify`:** 셀 이동과 화면 조작부 이동의 안내, 저장된 식과 미완성 원문의 상태 문구, 자료 확인 사유를 정리한다.
4. **최종 정돈 — `$impeccable polish`:** 위 동작이 정해진 뒤 100·125·150%와 밝게·어둡게에서 초점·줄바꿈·밀도를 확인한다.

각 단계를 하나씩, 함께, 또는 필요한 순서로 요청할 수 있다. 수정 후 `$impeccable audit`를 다시 실행하여 동일 조건의 문제와 점수를 비교한다.

실제 WPF/WebView2 호스트, Windows OS DPI, NVDA 등 낭독기, 터치 입력, 큰 자료의 실행 시간은 미검증이다. 나라장터·Mirror의 실제 수집과 상세 가져오기 흐름, 네이티브 확장과 파일 대화상자도 실행하지 않았다. 한국어 IME 조합 중 Enter 처리는 실제 Windows 환경에서 확인할 후속 항목이며 이번 다섯 문제에는 포함하지 않았다. 전체 대비 비율과 WCAG 200% 확대 시험도 수행하지 않았다. 이번 브라우저 모의 자료 결과를 앱 전체 검증으로 확대 해석하지 않는다.
