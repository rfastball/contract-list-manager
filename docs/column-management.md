# 열 관리 재설계 — 흐름식과 값 흐름 보표

2026-10-08. 상태: **지었다** — 화면(§6)과 백엔드(§11)가 앱에 섰다. 무엇이 앞 절과 다르게 섰는지는 §11.8.
대체하는 것: 같은 날의 앞선 재설계(입력열/가공열을 라디오와 종류 이름으로 고르던 목록 + 편집면)와
가공식 v1(물품 행 위의 `pick·distinct·format·join·at·get·count`).

## 1. 무엇이 구렸나

- **계산 여부와 값의 꼴을 한 칸에 섞었다.** `kind` 하나가 `text·choice·date·number·computed` 를 다
  담아, 가공열이 「꼴의 하나」처럼 드롭다운에 섰다. 계산 여부는 꼴과 직교한다 — 숫자 가공열도, 날짜 가공열도 있다.
- **가공이 물품목록 전용이었다.** 재료가 그 문서의 품목 행뿐이고, 연산은 「모아 쓰기」의 부품이었다.
- **중간이 보이지 않았다.** 결과 한 칸만 미리 보여, 중복이 몇 개 빠졌는지·번호가 빈 품목이 `책상()` 로
  찍히는지는 저장 뒤 표에서야 드러났다.

### 2.3 SQL 편집면 (폐쇄망)

- CodeMirror 6(`@codemirror/state·view·language·commands·autocomplete·lint`)은 MIT 이고,
  네트워크·워커를 쓰지 않는다(설치본 `dist` 를 훑어 확인). React 래퍼 없이 직접 감싼다.
- **`@codemirror/lang-sql` 은 쓰지 않는다.** 6.10.0 을 실측하니 토크나이저가 ASCII 글자만 식별자로 받아
  `세부품명` 이 오류 토큰이 되고 `v_공고품목` 이 `v_` + 오류로 갈린다. `[ ]` 는 SQLite 방언에서 식별자 따옴표가 아니고,
  자동완성은 `현재.` 뒤에 열 대신 뷰를 내며 한글 이름을 백틱으로 감싼다. 토크나이저는 내보내지 않아 고칠 수 없다.
  흐름식과 같은 `StreamLanguage` 로 작은 SQLite 하이라이터(유니코드 식별자·`"…"`·`[…]`·문자열·수·키워드)와
  자체 자동완성(계약면 뷰·열, `현재.` 열, 허용 함수)을 짓는다.
- 앱의 SQLite 는 SQLitePCLRaw 2.1.12(3.53 계열)다. 이 기계의 Python sqlite 3.45.1 에서
  `printf('%,d')`·`group_concat(… ORDER BY …)`·수학 함수를 직접 확인했다. 3.44 미만 소비자에게는
  `ORDER BY` 집계·`concat_ws`·`string_agg` 가 없다 → §7 최소 판.
- 검증: 읽기 전용 연결 + `sqlite3_set_authorizer` 로 계약면 뷰 READ·허용 함수만 통과시키고, 표본 행에서 실제로 돌린다.
- 남은 실측: 한글 식별자 자동완성, MS 한글 입력기 조합 중 자동완성·린트 동작(§8).

## 3. 모델

열은 **이름 · 꼴 · (있으면) 식** 이다. 계산 여부는 식이 있느냐로 정해진다. 꼴은 따로 정하는 성질이다.

| 정의 | 뜻 | 꼴 |
|---|---|---|
| `담당자 : 글` | 입력열 — 사람이 채운다 | 글 · 고르기(후보) · 날짜 · 숫자 |
| `진행상태 : 고르기(검토 전, 검토 중, 완료)` | 입력열 | |
| `품명과 번호 = 품목 |> …` | 가공열 — 식이 채운다 | 식의 결과 꼴(글 · 수 · 날짜)이 곧 열의 꼴 |
| `= SQL` | 가공열 — SQL 로 꺼낸 것 | SQL 결과는 글 |

- `:` 와 `=` 는 장식이 아니라 **문법**이다. 목록·정의줄·검색에서 같은 기호가 같은 뜻을 낸다.
- 값은 지금 규약 그대로 문서에 찍힐 문자열이다. 빈 값은 `''` 이고 NULL 이 아니다. 수는 `164,872,340` 로,
  날짜는 `2026/09/20` 로 찍힌다(§4.6).

### 3.1 전환

| 방향 | 동작 | 확인 |
|---|---|---|
| `:` → `=` | 입력값은 **지우지 않고 숨긴다**(지금 사용자 열 제거와 같은 규칙). 식이 칸을 채운다 | "입력한 값 n칸은 숨겨지고, 식을 지우면 돌아옵니다" |
| `=` → `:` 「값으로 굳히기」 | 지금 계산된 값을 각 행의 입력값으로 **쓴다**. 식은 비활성으로 남겨 다시 켤 수 있다 | `PlanDeletion` 처럼 **덮어쓸 칸 수를 세어 보인다** — 숨은 옛 입력값이 있으면 그 수도 |
| `=` 흐름식 → `= SQL` | 컴파일된 SQL 을 편집 가능한 원문으로 꺼낸다. **돌아올 수 없다** | 일방통행 확인 |

## 4. 흐름식

### 4.1 문법

```
정의    := 열이름 ( ":" 꼴 | "=" 식 )
식      := 원천 ( "|>" 단계 )*
원천    := "품목"                       -- 이 행의 정확한 차수에 속한 품목 목록
         | 연결 ( "." ( "품목" | 필드 ) )?
         | 필드                          -- 이 행의 기본 열(정정 반영 뒤 값)
         | 글자 | 수
연결    := "연결공고" | "연결접수" | "연결계약"   -- 자기 자신 종류는 없다
단계    := 동사 인자*
인자    := 필드 | 글자 | 수 | 조건 | 방향
글자    := '"' … '"'                     -- 서식 안의 {필드} 는 치환
조건    := 필드 비교 값 ( ("그리고"|"또는") 조건 )*
비교    := "=" | "≠" | ">" | "<" | "≥" | "≤" | "포함" | "비어있음" | "안비어있음"
```

- 원천과 동사는 한국어 낱말이다. 필드 이름에 공백·기호가 있으면 `[ ]` 로 감싼다(`[담당자 전화]`).
- **표준 출력은 하나다.** 단계 카드에서 고친 것은 표준 꼴로 다시 찍힌다. 흐름식 글에서 고친 것은 파싱해 단계로
  돌린다. 왕복이 깨지는 입력(주석·임의 공백)은 보존하지 않는다.
- 원천은 **품목 · 이 행의 기본 열 · 연결 문서** 셋이다(2026-10-08 사용자 확인: 연결 문서까지).
  다른 사용자 열·차수 목록은 첫 판에서 원천으로 받지 않는다. 의존 그래프와 순환 검사는 그 뒤로 미룬다.
- 연결 문서는 **사람이 확정한 연결**(ADR-004·ADR-021)을 따르고, 상대의 **최신 차수**를 본다(`v_공고` 와 같은 행).
  연결이 없으면 원천은 빈 행이다. 그 결과는 빈 값이지 오류가 아니다.
  연결 문서의 **사용자 열은 읽지 않는다** — 뷰 사이 순환을 구조적으로 막는다.

### 4.2 값의 꼴과 단계

식은 단계마다 꼴을 가진다: **행목록 · 값목록 · 행 · 값(글) · 수 · 날짜**.
「+ 단계」는 지금 꼴에서 쓸 수 있는 동사만 켠다. 끝 꼴은 값·수·날짜여야 저장된다.

| 무리 | 동사 | 들어감 → 나옴 | SQLite |
|---|---|---|---|
| 목록 | `거르기 조건` | 행목록 → 행목록 | `WHERE` |
| | `정렬 필드 [오름\|내림]` | 행목록 → 행목록 | `ORDER BY` (기본: 원래 순번) |
| | `고유 [필드, …]` | 행목록 → 행목록 (기준 필드가 같은 행은 처음 것만, 없으면 모든 필드) | `GROUP BY … min(순번)` |
| | `앞에서 n` | 목록 → 목록 | `LIMIT` |
| | `n번째` · `처음` · `마지막` | 목록 → 행/값 | `LIMIT 1 OFFSET` |
| | `서식 "…{필드}…"` | 행목록 → 값목록 / 행 → 값 | `||` |
| | `꺼내기 필드` | 행목록 → 값목록 / 행 → 값 | 열 선택 |
| | `잇기 "구분자"` | 값목록 → 값 | `group_concat(… ORDER BY 순번)` |
| | `줄여쓰기 n "{앞} 외 {나머지}종"` | 값목록 → 값 — n개까지는 잇고 넘으면 꼴대로 | `CASE count … ` |
| 셈 | `개수` | 목록 → 수 | `count(*)` |
| | `합계 · 최소 · 최대 · 평균 필드` | 행목록 → 수 | `sum(숫자로(필드))` … |
| 글 | `다듬기` · `바꾸기 "a" "b"` · `앞부분 "구분자"` · `뒷부분 "구분자"` · `자르기 시작 길이` · `앞채우기 길이 "0"` | 값 → 값 | `trim·replace·substr·instr·printf` |
| | `비면 값\|식` | 값 → 값 — `''` 이면 대신 | `coalesce(nullif(x,''), …)` |
| | `대응 "a"→"x", … [그외 "z"]` | 값 → 값 | `CASE` |
| | `만약 조건 "참" "거짓"` | 행/값 → 값 — 값을 견주면 필드 없는 마디는 지금 값, 필드를 적은 마디는 `비면` 이 읽는 바깥의 열(가공열은 이 행의 열, 맞춤 뷰는 `공고.공고명`) | `CASE WHEN` |
| | `경우 조건 → "글", … [, 그외 "글"]` | 값 → 값 — 위에서부터 견주어 처음 맞는 갈래의 글, 맞는 것이 없으면 그외(없으면 `''`). 갈래의 조건은 `만약` 의 값 조건과 같다(필드 없는 마디는 지금 값, 적은 마디는 바깥의 열). 저장 꼴은 `{"op":"cases","branches":[{"cond":[…],"then":"…"}],"otherwise":"…"}`, 갈래는 20개까지 | `CASE WHEN … THEN … ELSE … END` |
| 수 | `숫자로` | 값 → 수 (`,` 를 걷고 읽음, 못 읽으면 빈 값) | `CAST(replace(x, ',', '') …)` |
| | `더하기 · 빼기 · 곱하기 · 나누기 수\|필드` | 수 → 수 (나누기는 실수) | `+ - * /` (`* 1.0`) |
| | `반올림 [자리]` · `버림 [자리]` | 수 → 수 | `round` · 수학 함수 |
| | `천단위` · `그대로` | 수 → 값 | `printf('%,d')` |
| 날짜 | `날짜로` | 값 → 날짜 (`YYYY/MM/DD`·`YYYY-MM-DD`, 뒤 시각 무시) | `date(replace(substr(x,1,10),'/','-'))` |
| | `날짜더하기 n 일\|개월\|년` · `날짜차이 날짜식 [일]` | 날짜 → 날짜 / 수 | `date(…, '+n days')` · `julianday` |
| | `연도 · 월 · 분기` · `날짜서식 "YYYY년 M월 D일"` | 날짜 → 수 / 값 | `strftime` |

**넣지 않는 것:** 정규식(내장 함수가 아님), 한글 밖 대소문자 변환, 중앙값, 오늘·지금(외부 소비자 값과 어긋남).

### 4.3 예

```
품명과 번호 = 품목
  |> 고유 세부품명, 세부품명번호
  |> 서식 "{세부품명}({세부품명번호})"
  |> 잇기 ", "

대표 품명   = 품목 |> 꺼내기 세부품명 |> 고유 |> 줄여쓰기 1 "{앞} 외 {나머지}종"

품목 합계   = 품목 |> 합계 금액 |> 천단위

공고 기초금액 = 연결공고.기초금액

납품 남은 날 = 연결공고.납품기한 |> 날짜로 |> 날짜차이 계약일자 |> 그대로
```

### 4.4 오류와 빈 값

- 오류는 **그 오류를 만든 단계**에 붙는다(꼴이 안 맞음, 없는 필드, 서식의 짝 안 맞는 `{`). 뒤 단계는 「앞 단계 오류」로 흐려진다.
- 단계를 옮겨 꼴이 깨지면 막지 않고, 깨진 단계를 표시한다(Power Query 의 「중간 삽입」 경고 대신).
- 빈 목록 → `잇기` 는 `''`, `개수` 는 `0`. 범위 밖 `n번째` → `''`. `숫자로` 실패 → `''`. 계산 실패를 정상 빈 값으로 숨기지 않는다 —
  저장 전 검증과 표본 실행이 잡는다.

### 4.5 저장 꼴 (가공식 v2)

```json
{"version":2,"id":"생성된 ID","source":"flow",
 "flow":{"from":{"kind":"items"},"steps":[
   {"op":"distinct","fields":["세부품명","세부품명번호"]},
   {"op":"format","text":"{세부품명}({세부품명번호})"},
   {"op":"join","text":", "}]}}
```

- 단계의 원본은 JSON 이고, 흐름식 글은 그 JSON 의 표준 출력이다. 동사 이름(한국어)과 `op`(영문)는 1:1 로 대응한다.
- `{"version":2,"source":"sql","sql":"…"}` 는 SQL 탈출구다.
- v1 정의는 읽을 때 v2 로 옮긴다: `pick` 은 뒤 `format`·`get` 의 필드로 흡수하고, `at`+`get` 은 `n번째`+`꺼내기` 로 옮긴다.
  `v_가공열` 의 「가공식」은 v2 JSON 을 낸다 — 규약 문서를 같은 커밋에서 고친다.

### 4.6 결과의 찍힘

끝 꼴이 수이면 기본은 `천단위`(정수)다. 소수는 반올림하지 않은 그대로 찍는다.
`그대로` 는 쉼표 없는 숫자를 낸다. 끝 꼴이 날짜이면 `YYYY/MM/DD` 로 찍는다. 모든 결과는 `coalesce(…, '')` 로 감싼다.

## 5. SQL 탈출구

- 꺼낸 SQL 과 사람이 고친 SQL 은 **스칼라 부질의 하나**다. 바깥 행은 별칭 **`현재`** 로 읽는다.

  ```sql
  SELECT group_concat(세부품명 || '(' || 세부품명번호 || ')', ', ' ORDER BY 순번)
  FROM v_공고품목 WHERE 입찰공고번호 = 현재.입찰공고번호
  ```
- 읽을 수 있는 것은 **계약면 뷰**(이름이 약속된 것)뿐이다. 내부 표(`notice_item` 등)는 막는다 — 스키마 판올림이 사용자 식을 깨지 않게 한다.
- 흐름식 컴파일러도 같은 SQL 을 낸다. 꺼내기는 컴파일 결과를 그대로 찍는 것이고, 두 벌을 두지 않는다.
  성능 실측에서 뷰 위의 뷰가 느리면 그때 내부 표 직결을 컴파일러 안에만 둔다.
- 검증(저장 전, 매 편집 디바운스):
  1. 읽기 전용 연결과 `PRAGMA query_only` 를 쓴다.
  2. authorizer 는 `SELECT`·계약면 뷰 `READ`·허용 함수만 통과시키고, `ATTACH·PRAGMA·쓰기·CREATE` 는 거절한다.
  3. `SELECT (식) FROM <대상 뷰> AS 현재 LIMIT 0` 으로 prepare 한다. 이때 구문 오류와 뷰 순환(`circularly defined`)이 잡힌다.
  4. 표본 행에서 실제로 돌려, 한 행이 두 값 이상을 내면 거절한다.
- 뷰 이름을 바꾸는 판올림(ADR-034)은 SQL 열을 깰 수 있다. 판올림은 `Views.LegacyNames` 로 사용자 SQL 의 옛 이름을 고쳐 쓰거나,
  못 고치면 그 열을 「깨진 식」으로 세우고 뷰 전체를 실패시키지 않는다.

## 6. 화면 — 값 흐름 보표

한 작업 영역, 세 부분: **위 정의줄 · 왼쪽 열 목록 · 가운데 보표.**

### 6.1 열 목록

- 자료 종류는 머리의 분할 단추 `접수 · 공고 · 계약` 으로 고른다(드롭다운 아님). 통합에서 들어오면 계약.
- 줄마다 정의의 머리를 찍는다: `: 담당자  글`, `: 진행상태  고르기`, `= 품명과 번호  …잇기`.
  연산자 기호가 종류 표시다. 「입력열·가공열」 낱말 꼬리표와 종류 필터는 없다.
- 검색칸도 같은 문법을 쓴다: `=` 로 시작하면 가공열만, `:` 로 시작하면 입력열만 보인다.
- 맨 아래 `+ 새 열` 줄: 이름을 치고 `:` 또는 `=` 를 치면 그 종류로 열린다(단추 `: 입력` `= 가공` 도 함께 둔다).
- 순서 바꾸기(↑↓)와 지우기는 고른 열의 정의줄 메뉴에 둔다.

### 6.2 정의줄

`[열 이름] [: | =] [꼴 또는 원천]` — Power BI 수식줄처럼 한 줄로 읽힌다. 연산자 칸을 눌러 바꾸면 §3.1 전환 확인이 뜬다.
오른쪽에 결과 꼴(글·수·날짜)과 상태(`저장됨` · `변경됨` · `오류 1`)를 둔다.

### 6.3 `:` 입력열 편집

- 꼴 분할 단추 `글 · 고르기 · 날짜 · 숫자` 를 둔다. 고르기는 후보를 칩으로 넣는다.
- 아래에 목록 미리보기(앞 열 두 개 + 이 열)를 두고, 「입력해 보기」 값은 저장되지 않는다고 적는다.

### 6.4 `=` 가공열 편집 — 보표

탭 `단계 · 흐름식 · SQL`.

**단계(기본).** 행은 단계, 열은 표본 문서 3건(바꿀 수 있음)이다. 칸은 **그 단계까지의 값**을 보인다.

```
 단계                                표본 A (3품목)            표본 B (1품목)
 품목                                3행                       1행
 고유  세부품명, 세부품명번호         2행  · 1행 겹쳐 빠짐       1행
 서식  "{세부품명}({세부품명번호})"   책상(001) / 의자(002)      의자()  ⚠ 번호 빈 값 1
 잇기  ", "                          책상(001), 의자(002)       의자()
 + 단계
```

- 목록은 행 수와 앞 몇 값을 칩으로 보이고, 줄어든 수(「1행 겹쳐 빠짐」)와 빈 값 수를 붙인다(Tableau 프로필 카드).
- 단계 줄을 고르면 아래 **단계 설정**이 열린다. 서식 단계에서는 표본 품목 표의 값을 눌러 `{필드}` 를 끼운다.
- 「+ 단계」는 지금 꼴로 걸러진 동사 고르개다: 목록 · 셈 · 글 · 수 · 날짜 묶음, 동사마다 한 줄 설명. 쳐서 찾기를 지원한다.
- 키보드: ↑↓ 단계 이동, Alt+↑↓ 옮기기, Delete 지우기, Enter 설정 열기.
- 원천이 비어 있는 새 `=` 열은 **빠른 시작**을 보인다:
  - 원천: `품목` · `이 행의 열` · `연결공고/접수/계약`
  - 묶음: 「이름(번호) 나열」 · 「첫 품목 외 n종」 · 「품목 수」 · 「금액 합계」
  - 묶음은 보통 단계로 깔린다.

**흐름식.** CodeMirror 로 편집한다. 동사·필드 자동완성, 꼴 오류 밑줄을 둔다. 고칠 때마다 파싱해, 성공하면 단계로 돌리고 실패하면 줄에 오류를 붙인다.

**SQL.** 컴파일된 SQL 을 읽기 전용으로 보인다. 「SQL로 꺼내 직접 편집」은 일방통행 확인을 거친다. 그 뒤로는:
- 자체 SQLite 하이라이터로 편집하고, 계약면 뷰·열과 `현재` 를 자동완성한다(§2.3).
- 검증 오류는 밑줄로, 표본 결과는 아래 표로 보인다.

### 6.5 표 안

- 가공열 머리글 앞에 `=` 를 둔다.
- 가공열 칸에서 F2·두 번 누르기를 하면 편집 대신 작은 안내가 뜬다. 안내에는 식 첫 줄과 「식 고치기」가 있다.

### 6.6 좁은 창

60rem 이하에서는 목록과 편집이 갈마든다. 보표의 표본은 1건으로 접히고, 다른 표본은 고르개로 바꾼다.

## 7. 계약면에 닿는 것

- `v_가공열.가공식` 이 v2 JSON 을 낸다. 「결과타입」에 `date` 를 더한다.
- 가공열 SQL 이 쓰는 함수 때문에 **소비자 SQLite 3.44 이상**을 규약에 적는다(`group_concat … ORDER BY`·`printf('%,d')`).
  3.44 미만을 지원해야 하면 `잇기` 를 정렬된 부질의 위의 `group_concat` 으로 낮춘다 — 순서가 문서상 보장되지는 않는다.
- 가공열은 값을 저장하지 않는다는 원칙(외부 읽기 연결에서도 같은 값)을 유지한다. 앱 전용 함수는 쓰지 않는다.
- 「값으로 굳히기」는 입력값을 쓰는 일괄 쓰기다. 쓰기 전에 덮을 칸 수를 센다.

## 8. ADR 초안 — ADR-038 가공열은 흐름식, SQL 은 일방통행 탈출구

- **결정:** 계산 여부를 열의 성질로 두고 `이름 : 꼴` / `이름 = 식` 문법으로 드러낸다.
  가공식은 원천(품목·행·연결 문서)에서 시작하는 단계 목록이다. 원본은 JSON, 글은 표준 출력이다.
  사람이 고친 SQL 은 계약면 뷰만 읽는 스칼라 부질의로 받는다.
- **뒤집는 것:** 계약면 규약 §3 「임의 SQL·코드는 받지 않는다」. 받되, 읽기 권한을 계약면 뷰로 묶고 표본 실행으로 검증한다.
- **버린 안:** SQL 하나(카드로 돌아올 수 없음) · 영문 SQL 파이프 키워드(한국어 사용자에게 덜 읽힘) ·
  예제 기반 추론(추론 엔진 신뢰 문제, 보류).
- **확인할 것:**
  - 한글 입력기 조합 중 CodeMirror 자동완성·린트(MS 한글 입력기, 식별자 안·줄머리·`(` 옆)
  - 소비자(문서 생성기)의 SQLite 판
  - 뷰 위 뷰 컴파일의 성능(계약 수천 건 × 가공열 10개)

## 11. 백엔드 판 (2026-10-08 착수 승인)

§4·§5 를 실제 SQLite 로 세운다. 조사로 드러난 사실 셋이 앞 절을 고친다 — 이 절이 우선한다.

### 11.1 앞 절을 고치는 사실

1. **품목 뷰는 최신 차수만 낸다**(`LatestNotice`·`LatestContract`·`LatestRequest`). 가공열은 `v_공고차수`·`v_계약차수` 의 옛 차수 행에도 붙으므로,
   흐름식 컴파일러는 v1 처럼 **내부 표의 정확한 차수**(`{entity}_item i WHERE i.{entity}_base = … AND i.seq = …`)를 읽는다.
   §5 의 "흐름식 컴파일러도 같은 SQL 을 낸다"를 거둔다. 「SQL로 꺼내기」는 같은 AST 를 **계약면 뷰용으로 옮겨 쓰는** 두 번째 출력기다.
   두 출력의 결과가 최신 차수에서 같음을 시험으로 묶는다(§11.7).
   SQL 열은 계약면 뷰를 읽으므로 **최신 차수 기준**이다 — 옛 차수 행에서 품목 뷰를 거르면 빈 값이 된다. 규약에 적는다.
2. **연결의 개수.** `project_link` 는 계약 계열당 하나지만 공고 건(`notice_group`)은 여러 계약에 붙는다. `request_link` 는 1:1.
   | 이 행 | 원천 | 꼴 |
   |---|---|---|
   | 계약 | `연결공고` · `연결접수` | 행 |
   | 공고 | `연결접수` | 행 |
   | 공고 | `연결계약` | **행목록** |
   | 접수 | `연결공고` | 행 |
   | 접수 | `연결계약` | **행목록** |
   `연결X.필드` 줄임은 꼴이 행일 때만 쓴다. 행목록이면 `연결계약 |> 처음 |> 꺼내기 계약금액` 처럼 목록 동사를 거친다(꼴 검사가 막는다).
   연결 공고는 그 건의 **현행 공고**(`건현행` / `NoticeGroups.현행공고` 와 같은 규칙)이고, 연결 계약·접수는 각 계열의 최신 차수다.
3. **바깥 행 `현재`.** 사용자 열이 붙는 뷰(`v_공고`·`v_공고차수`·`v_계약`·`v_계약차수`·`v_접수`)는 가공열이 하나라도 있으면
   `SELECT 현재."열1", …, (식) AS "가공열", … FROM (<지금의 뷰 본문에서 가공열을 뺀 것>) AS 현재` 로 한 겹 감싼다.
   - 바깥 목록은 지금 열 순서를 **그대로** 하나씩 적는다(사용자 열의 `sort_order` 가 입력열·가공열을 섞는다). 계약면 박제(`views.txt`)가 바뀌지 않아야 한다.
   - 자기 행 원천·필드는 `현재."열이름"` 으로 읽는다 — 정정(`field_override`)을 마친 값이다. 원천으로 쓸 수 있는 자기 행 열은 **기본 열**뿐(사용자 열 제외).
   - 품목은 `i.{entity}_base = 현재.<본번호열> AND i.seq = 현재.차수` 로 정확한 차수를 잡는다(본번호·차수 열 이름은 뷰마다 확인).
   - 연결 문서의 필드는 그 개체의 **덮개 식**(`Face`)을 그 행 별칭으로 다시 불러 읽는다 — 상대 뷰를 읽지 않으므로 뷰 사이 순환이 생기지 않는다.
     덮개 식을 이름으로 꺼내는 길이 없으면 `Views` 안에 하나 만든다(열 이름 → 별칭을 받는 식). 새 공개 뷰를 만들지 않는다.

### 11.2 저장과 판올림

- `user_column.options` 가 v2 JSON(§4.5)을 담는다. **스키마 22**: 기존 v1 가공식을 v2 로 옮겨 쓴다(옮기는 규칙은 §4.5, TS `flow/migrate.ts` 와 같은 결과).
  `kind` 는 그대로 둔다(`computed` = 식이 있음). `v_가공열` 의 「가공식」은 v2 를, 「결과타입」은 `text·number·date` 를 낸다.
- 정의를 저장할 때 C# 이 다시 검사한다 — 화면을 믿지 않는다:
  1. JSON 모양 확인
  2. 꼴 검사(§4.2 규칙과 같은 표)
  3. 컴파일
  4. 그 열이 붙는 모든 뷰를 한 트랜잭션에서 다시 짓고 prepare 한다
  5. 표본 실행
  
  하나라도 실패하면 되돌리고, 오류는 **단계 번호**를 담아 돌려준다.

### 11.3 컴파일러 (C#, `ComputedColumn` 을 대체·확장)

- 입력: v2 AST, 대상 개체, 바깥 별칭 `현재`. 출력: `coalesce((…), '')` 스칼라 식.
- 단계마다 꼴을 따라 SQL 조각을 쌓는다:
  - 행목록은 `(__order, 필드…)` 를 내는 부질의
  - 값목록은 `(__order, __value)`
  - 행은 `LIMIT 1` 부질의
  - 값·수·날짜는 스칼라
- 동사별 SQLite 는 §4.2 표를 따른다. 앱 전용 함수 없음. `잇기` 는 `group_concat(__value, sep ORDER BY __order)`.
- 수는 `숫자로` 가 쉼표를 걷고 `CAST … AS REAL`·정수 판정을 한다. 끝 꼴 수의 기본 찍힘은 정수면 `printf('%,d')`, 아니면 그대로(§4.6). 날짜 끝은 `strftime('%Y/%m/%d')`.
- **앞부분 컴파일**: 단계 k 까지만 잘라 컴파일할 수 있어야 한다(§11.4).

- 「SQL로 꺼내기」는 단계 이름을 줄 주석으로 붙이고 결과 열을 `결과`로 표시한다. 주석·별칭은 기존 SQL 검증을 그대로 통과하며 읽기 권한이나 허용 문법을 늘리지 않는다.
- 목업 `flow/sql.ts`도 C#과 같은 `__order` 순서 열을 쓴다. 정렬 후 `꺼내기`·`서식`으로 값을 바꿔도 순서가 남고, `마지막`은 그 순서를 뒤집어 한 줄을 고른다. 연결계약 목록, 숫자 변환·표시, 음수 날짜 더하기도 같은 규칙이다.
- C#이 실제 앱의 정본이다. 공유 사례표는 TS 평가기와 C#의 내부·공개 SQL을 실행해 비교한다. TS가 만든 목업 SQL은 기존 프런트 시험에서 생성 구조를 검사하며, 실데이터 저장·권한 검증을 대신하지 않는다.

### 11.4 브리지

| 메서드 | 무엇 | 쓰기? |
|---|---|---|
| `columnContext(entity)` | 지금 것 + `available`: 자기 행 기본 열, 품목 필드, 연결 원천과 꼴·필드 | 읽기 |
| `traceComputedColumn(entity, json)` | 표본 3건(최신 문서)에 대해 원천과 단계 k 마다 그 시점 값. 목록은 `{kind:"list",count,items(앞 5),dropped,blank}`, 값은 `{kind:"value",text,blank}`. 단계 오류는 그 단계에 붙이고 뒤 단계는 `blocked` | 읽기 |
| `compileComputedColumn(entity, json)` | 흐름식 → 「SQL로 꺼내기」용 계약면 SQL 문자열 | 읽기 |
| `validateComputedSql(entity, sql)` | §5 검증 + 표본 결과 | 읽기 |
| `saveComputedColumn(entity, name, json, previousName)` | v2 저장(§11.2) | 쓰기 |
| `planFreezeColumn(entity, name)` | 「값으로 굳히기」가 쓸 칸 수, 숨은 옛 입력값 수 | 읽기 |
| `freezeColumn(entity, name)` | 각 **계열의 최신 차수** 값을 입력값으로 쓴다(ADR-012: 사람 값은 계열에 매단다). 식은 `options` 에 비활성으로 남긴다 | 쓰기 |

- 화면의 `types.ts` 주석에 적힌 계약(시안이 목업으로 정한 모양)을 따른다. 어긋나면 목업을 고친다.
- 새 메서드는 `Bridge.Writes` 또는 `ViewerAllowed` 에 넣는다. 열람 중 쓰기는 막는다.

### 11.5 SQL 열

- 저장 꼴 `{"version":2,"source":"sql","sql":"…"}`. 뷰에 `(사용자 SQL) AS "열"` 로 들어간다(§11.1-3 의 감싼 바깥 SELECT 안, `현재` 가 보인다).
- 검증:
  - 연결: 읽기 전용 연결(`OpenReadOnly`)에 `query_only`.
  - authorizer: `SQLitePCL.raw.sqlite3_set_authorizer` 를 건다(`connection.Handle`). 통과는 셋뿐이다.
    - `SQLITE_SELECT`
    - `SQLITE_READ` — 표가 계약면 뷰(`Views.Names` 중 `v_가공열` 제외)이거나, 그 뷰가 안에서 읽는 표일 때. authorizer 는 뷰 펼침 안의 READ 도 부른다 — 바깥 사용자 SQL 과 뷰 내부를 가르는 방법을 실측해 정한다. 못 가르면 prepare 전에 SQL 토큰에서 `FROM`/`JOIN` 대상 이름을 뽑아 허용 목록과 대조하는 것으로 대신한다.
    - `SQLITE_FUNCTION` — 허용 목록.
  - 순서: 구문·순환 오류는 prepare, 두 값 이상을 내는 행은 표본 실행이 잡는다.
- SQL 열은 단계 카드로 돌아오지 않는다.

### 11.6 계약면·문서

- `docs/dataset-contract.md` §3 「사용자 정의 가공열」을 v2 로 고친다:
  - 문법·연산 표 요약, 원천, 연결의 꼴
  - SQL 열(계약면 뷰만, 최신 차수 기준)
  - 소비자 SQLite **3.44 이상**
  - 「값으로 굳히기」

### 11.7 시험

- **공유 사례표** `tests/flow-cases.json`(새 파일): 사례마다 AST, 기대 꼴/오류 단계, 기대 최종값을 담는다. 재료는 목업과 같은 품목(겹치는 책상 행 포함)·연결 행이다.
  vitest(`flow/`)와 xunit 이 **같은 파일**을 읽는다 — 두 꼴 검사·평가가 어긋나면 한쪽이 붉어진다.
- 컴파일된 내부 표 SQL 과 꺼낸 계약면 SQL 의 결과가 최신 차수에서 같은지 확인한다.
- `v_공고차수` 의 옛 차수 행이 그 차수의 품목으로 계산되는지 확인한다.
- `views.txt` 가 바뀌지 않는지 확인한다.
- SQL 열 검증: 쓰기·ATTACH·PRAGMA·내부 표 읽기 거절, 순환 거절, 다중 행 거절.
- 굳히기: 센 수와 실제로 쓴 수가 같은지 확인한다.
- 성능: 계약 3,000건 × 가공열 10개(품목 나열·연결 필드 섞어)에서 `SELECT * FROM v_통합` 시간을 재어 커밋 본문에 적는다.

### 11.8 지은 것 (2026-10-08)

- **코어**(8bafab8): `Flow`·`FlowCompiler`(내부 표 출력기 + 「SQL로 꺼내기」 계약면 출력기, 앞부분 컴파일), 스키마 22,
  면 뷰 감싸기, 공유 사례표 `tests/flow-cases.json`. `views.txt` 는 바뀌지 않았다.
- **다리**(§11.4 표 전부): `columnContext.available`(연결의 `many` 포함) · `traceComputedColumn` · `compileComputedColumn` ·
  `validateComputedSql` · `planFreezeColumn` · `freezeColumn`. 쓰기는 `freezeColumn` 하나라 `Bridge.Writes` 에, 나머지는 열람 허용.
  앞 판 편집기가 쓰던 `computedFields`·`previewComputedColumn` 은 다리에서 걷었다.
- **SQL 열 검증**(§11.5): authorizer 는 뷰 안쪽 읽기에 뷰(또는 뷰 안 CTE, `사슬`) 이름을 넘겨 바깥과 가를 수 있었다. 다만
  뷰 위의 `count(*)` 를 밑 표 읽기로 바꿔 쓰는 최적화가 그 읽기를 바깥으로 보고해(`v_공고차수` → `notice`), 이름 단위
  허용 목록을 함께 둔다 — 글에 적힌 이름이 스키마 객체·`sqlite_`·`pragma_` 이면 계약면 뷰 열 개여야 한다. 사용자 CTE 는
  안쪽 읽기로 보고되므로 `WITH` 를 받지 않는다. 함수 허용 목록에는 창 함수를 넣었다(뷰 안의 `row_number` 가 바깥으로 보고된다).
  `;`·짝 없는 괄호·닫히지 않은 글자/주석은 준비 전에 막는다 — 뷰 정의는 여러 문장을 한 번에 돌린다.
- **깨진 정의**: 뷰를 지을 때 가공열을 하나씩 준비해 보고 깨진 것은 빈 글로 세운다. 까닭은 면 뷰 정의 안 주석에 남고
  `userColumns` 의 `broken` 으로 화면에 간다(목록 꼬리 · 정의줄 아래 한 줄). 상태를 담는 표·뷰는 더하지 않았다.
- **굳히기**: 계열마다 면 뷰(최신 차수)의 값을 `user_field` 에 쓰고, 값이 빈 계열의 옛 입력값은 지운다. 확인 창이 센 칸 수를
  함께 보내 그 사이 자료가 바뀌었으면 쓰지 않는다. 식은 `options` 에 남아 `=` 로 다시 켜면 같은 식별자로 돌아온다.
- **화면**: 보표는 다리의 `traceComputedColumn`, SQL 탭은 `compileComputedColumn`, SQL 편집은 `validateComputedSql`(300 ms
  디바운스), 성질 바꾸기 확인 창은 `planFreezeColumn` 의 수를 보인다. 목업 다리는 같은 이름을 TS 평가기로 지킨다.
- 성능: 계약 3,000건 × 가공열 10개에서 `SELECT * FROM v_통합` 823 ms(가공열 없이 86 ms).
- 남은 것: MS 한글 입력기 조합 중 CodeMirror 자동완성·린트, 실제 WPF 창에서의 굳히기·SQL 편집, 문서 생성기의 SQLite 판(3.44 이상).
