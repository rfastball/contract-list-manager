# 계약 목록 UX / UI

## 작업 방향

모드: Operate. 기존 글꼴·색상·테마를 유지하고, 자료 탐색과 실행할 작업의 위계를 정리한다.
주 사용 환경은 Windows 데스크톱이며 좁게 줄인 창에서도 조작할 수 있어야 한다.

## 작업 흐름

1. **넣기** — 자료는 브라우저 확장 수집과 ERP JSON 검토로 들어온다(ADR-028). 둘 다 왼쪽 메뉴의 **나라장터**
   화면에 있다 — 확장 설치·상태, 오늘 들어온 자료, 고급(JSON 검토·매핑). 새 수집은 해당 갈래에 `+N` 으로 선다.
   자료가 없으면 나라장터로 안내한다. 계획·현황과 계획 엑셀 설정 입구는 동결해 숨겼다.
2. **찾기** — 왼쪽 맨 위의 대시보드, 수집의 나라장터, 자료의 접수 · 공고 · 계약, 내 보기 순서로 범위를 정한다. 메뉴는 독립된 행이며
   흰 컨테이너와 세로 연결선을 두지 않는다. 현재 메뉴의 배경·표시와 키보드 초점은 구분한다.
   검색은 현재 화면에 적용되고 결과 건수와 전체 건수를 함께 보인다.
3. **검토** — 통합 구조에서 접수·공고·계약을 같은 줄로 읽는다.
   ‘빈 단계 있는 건’은 접수 또는 공고가 없거나 계약이 0건인 조달 건만 남긴다.
   이것은 저장된 자료의 빈 자리이며 실제 업무 누락이나 진행 지연의 판정이 아니다.
4. **수정** — 관계는 수집 자료의 명시 참조로 재구성하며 수동 공고 연결은 제공하지 않는다. 표의 검색·열 관리·내보내기는 한 도구 모음으로
   묶고 바로 아래 작업 줄에서 행 선택 또는 셀 범위에 맞는 작업을 제공한다. 차수 보기의 편집 잠금과
   삭제 전 영향 확인은 유지한다. 여러 셀 변경은 검토 후 한 번에 저장하며 일부만 반영하지 않는다.
5. **열 관리** — 표 도구 모음과 사용자 열 머리글에서 전용 작업공간을 연다. 열은 `이름 : 꼴`(입력열)과
   `이름 = 식`(가공열)이고, 가공열은 값 흐름 보표로 단계마다의 값을 보며 고친다.
   설정에는 열 관리 바로가기를 중복해서 두지 않는다. 열 정의는 전용 작업공간에서 편집한다.
6. **내보내기** — 검색 결과·선택한 행은 현재 표의 순서를 유지한 시트 한 장, 전체 자료는 검색·선택과
   무관한 `Views.Exported` 열 장이다. 전체 자료 내보내기는 설정의 **자료 관리**에서만 제공한다.
   백업·복구(.pclm)와 엑셀 공유(.xlsx)를 설명으로 구분한다. 제출·취합은 설정에 있다.

## 첫 화면과 상호작용

- 대시보드는 제목·보기 방식 / 간결한 DB 집계·기준 시각 / 단계 분포 / 검색·정렬 / 조달 자료 표 순서다. 집계 기준은 접어 두고 기본 상태에서는 결과를 가리는 설명을 반복하지 않는다.
- 기본 브리핑의 「진행 단계」는 최신 문서를 조달 건으로 묶어 공고 대기·공고중·계약 대기·계약 완료 네 단계와 0건을 보인다. 알 수 없는 일정·현행 공고는 네 단계에 억지로 포함하지 않고 다섯째 칩 「단계 미정」에 둔다 — 다섯 칩의 합이 전체다. 행의 「자료 확인 필요 n」 표시는 그 이유를 툴팁으로 보인다. 단계와 검색을 함께 적용하며 계약 건명과 현행을 정하지 못한 공고 번호도 찾는다.
- 공고중은 게시 시각부터 개찰 전까지며 재공고도 같은 기준이다. 번호가 있지만 날짜가 없는 계약 초안은 계약 대기, 모든 계약에 번호와 유효한 계약일이 있으면 계약 완료다. 현행 취소공고에 계약이 없는 건은 자료 확인 필요이고, 해지된 날짜 있는 계약은 계약 체결의 이력으로 남긴다. 계약 완료가 납품·이행 완료를 뜻하지 않는다.
- 「납품기한」은 기한 경과·오늘·오늘부터 7/30일·기한 미확인·지정 기간과 계약/번호/거래처/기관/품목 검색을 결합한다. 계약과 품목 중 해당 날짜가 있는 계약을 한 번씩 세며, 품목으로만 검색되면 그 품목의 기한을 조회한다. 해지 계약은 기본 제외하고 체크하면 포함한다. 가장 이른 해당 기한과 품목명 또는 계약 기한을 보여 주며 펼친 행에서 품목별 기한 원문·조회 날짜·남은 기간을 읽는다.
- 빈 품목 기한에는 유효한 계약 기한을 적용했다고 표시하고, 해석되지 않는 기한 원문에는 적용하지 않는다. 모든 품목 기한이 유효하면 계약 머리 기한이 없다고 미확인으로 세지 않는다. 날짜와 미확인 품목이 섞인 계약은 기한 조회와 미확인 조회에 함께 나타난다. 조회 기간은 시작일·종료일을 포함하며 7/30일은 오늘부터이고 지난 날짜를 포함하지 않는다.
- 두 대기 단계는 중립 회색, 공고중은 파랑, 계약 완료는 초록이다. 선택 테두리·굵기는 단계의 색 의미를 유지한다. 빨강은 지난 납품기한, 주황은 오늘부터 7일까지에만 사용한다. 자료 확인 필요는 중립색이다.
- 문서 번호는 기존 자료 표를 연다. 돌아오면 진행/기한 조회 방식과 검색·조건·페이지·펼친 행을 유지하며 자료 목록의 최신·전체 차수 선택과 분리한다. 수집 계약금액(해지 포함)은 확인된 금액만 더하며 금액 확인 건수와 0원·미확인을 구분한다. 자료 새로고침은 기존 조회·변경 감지 흐름을 사용한다.
- 설정은 자료 관리 / 제출·취합 / 화면 표시 / 보기 구성 / 앱 실행으로 구성한다. 열 관리·브라우저 수집 바로가기를 반복하지 않는다. 글자 크기와 테마는 즉시 적용하고 로컬에 저장하며, 앱 실행에는 알림 영역 두기와 Windows 자동 실행을 유지한다.
- 보기 구성에서는 정의 패키지를 주고받는다. 표 정렬·검색은 현재 세션 상태이고 별도 저장된 화면 레이아웃이 없어 포괄 초기화 기능은 제공하지 않는다.
- 브리핑의 진행/기한·검색·확인 필요 필터와 구조의 빈 단계 필터는 각 탐색 방식의 결과를 좁힌다. 결과가 없어도 조건 초기화로 복구한다.
- 빈 자료, 검색 결과 없음, 읽는 중, 오류 알림을 구분한다. 오류는 보조기술에도 알린다.
- 탭은 방향키·Home·End, 검색은 Ctrl+F, 표와 구조는 기존 이동·편집 단축키를 유지한다.
- 760px 이하에서는 탐색을 위로 옮기고 단계는 세로로 잇는다. 표는 자체 영역에서 가로 스크롤한다.
- 개발 브라우저에는 ‘미리보기 · 예시 자료’를 표시한다.
- 화면 전환 중 이전 응답은 버리고, 읽기 실패에는 ‘다시 읽기’를 제공한다.
- 구조에서 선택한 건은 표 검색으로 이어진다. 차수 내역은 펼쳐 읽으며 검색 중에도 접기·초기화가 가능하다.
- 설정·확인 창은 네이티브 dialog의 초점 제한과 Esc 닫기를 사용한다. 저장·삭제 실행 중에는 닫기를 막는다.
- 확장 연결 도움말은 앱 실행, 권한·호스트 등록, 새로고침 순서로 복구를 안내한다.

## 표 선택과 일괄 작업

- **행 선택:** 체크박스로 고르고 Shift+클릭으로 범위를 늘린다. 머리 체크박스는 검색 결과 전체를 고른다.
  활성 셀 하나만으로 자료 삭제를 노출하지 않는다. 행 선택과 셀 범위는 별도 모드 전환 버튼 없이
  체크박스와 셀 조작으로 구분하며 한 번에 하나만 활성화한다. 검색을 바꾸면 선택을 해제한다.
- **셀 선택:** 드래그·Shift+클릭·Shift+방향키로 사각형을 고른다. 표에서 Ctrl+A는 현재 검색 결과의 셀,
  행 체크박스에서 Ctrl+A는 검색 결과의 행, 입력창에서 Ctrl+A는 편집 중인 글자를 선택한다.
  Shift+Space는 현재 셀 범위의 행을 선택한다. Delete는 내용 비우기, Ctrl+Delete는 수집 원래 값 복원이다.
- **일괄 입력:** 선택한 행의 사용자 입력열에 같은 값을 넣거나 셀 범위에 Excel의 탭·줄바꿈 값을 붙여넣는다.
  변경 전·후를 검토한 뒤 적용한다. 잠긴 칸·다른 자료의 열·잘못된 값·없어진 차수·동시에 바뀐 값은
  전체 적용을 막는다. 입력열은 계열 전체, 수집값 정정은 해당 차수에 적용된다. 원래 값 복원은 일반 실행 취소와 다르다.
- **자료 삭제:** 통합에서는 접수·공고·계약 중 삭제할 자료 종류를 명시한다. 반복 행의 같은 자료는 중복 제거하고,
  선택한 차수 또는 전 차수의 하위 자료·정정값·입력값·실제로 사라지는 연결을 합집합으로 센다.
  조달 흐름 전체를 지운다는 뜻이 아니다. 확인 후 자료가 바뀌면 다시 검토하며 최종 삭제는 한 트랜잭션으로 처리한다.
- **반출:** 검색 결과·선택한 행 내보내기는 현재 열과 정렬 순서 그대로 한 시트에 담는다. 셀 범위는 복사한다.
  전체 자료 열 장은 통합·접수·접수품목·공고·공고품목·계약·계약품목·ERP원천·계약업체·ERP접수다.
  전체 내보내기에 차수 뷰는 포함하지 않지만 차수 표의 검색 결과는 그 표 한 장으로 내보낼 수 있다.

## 열 정의 편집

화면의 모양과 행동은 [열 관리 재설계](column-management.md) §6 이 정본이고, 무엇이 실제로 섰는지는 §11.8 에 있다.
요약하면 왼쪽 열 목록(줄머리 `:`/`=`, 검색 접두로 거르기), 위 정의줄(이름·연산자·요약·상태), 가운데 편집면이다.

- 입력열은 꼴 분할 단추와 목록 미리보기(입력해 보기 값은 저장하지 않는다)를 둔다.
- 가공열은 `단계 · 흐름식 · SQL` 탭이다. 단계 탭의 보표는 표본 문서 셋에서 단계마다 그 시점의 값을 보이고,
  오류는 그 단계에 붙으며 뒤 단계는 흐려진다. SQL 은 일방통행 확인 뒤에만 꺼내 고치고, 고칠 때마다 앱이 검사해
  거절 까닭과 표본 결과를 보인다.
- 연산자를 눌러 성질을 바꾸면 확인 창이 먼저 칸 수를 센다 — 가공열로 바꾸면 숨겨질 입력값, 값으로 굳히면 쓸 칸과
  덮이거나 지워질 옛 입력값.
- 저장된 식이 깨져 뷰에서 빈 값으로 나가는 열은 목록 꼬리와 정의줄 아래에 까닭을 보인다.
- 정의는 명시적으로 저장하며 저장 오류가 나면 초안을 유지한다. 편집한 채 이동하면 **계속 편집 / 변경 버리기 /
  저장 후 이동**을 고른다. 열람 창에서는 정의를 읽고 표본을 볼 수 있지만 고치지 못한다.
  통합에는 계약 사용자 열만 표시되며 공고·접수 열은 해당 목록에서 확인한다.

## 보완 검증 (2026-09-24)

- 기존 테스트 파일에 회귀 사례 2개를 추가했다. 지연된 이전 응답의 덮어쓰기 방지와 선택 건의 표·연결 이동은 App 테스트가 담당한다. 접기·차수 표시·현황 단추·누락된 연결 대상·확인창 초점은 기존 소유 테스트를 확장하고 이전 표시 방식의 단언을 교체했다.
- 테스트 7개 파일, 100개 통과. 직전 98개/11.49초에서 100개/13.14초로 증가했다(통제된 성능 비교는 아님). 새 테스트 파일·의존성·CI 경로·무거운 자동 실행은 없으며 coverage 기준은 유지했다.
- 프런트엔드 빌드와 별도 출력 경로의 WPF 빌드가 통과했다. WPF 경고·오류는 0개다.
- 브라우저에서 넓은 창과 760px 창, dialog 초기 초점·Esc 복귀·배경 비활성화, 차수 Enter 펼치기, 선택 접수의 표 이동을 확인했다. 확장 미리보기는 280px 저장 결과 조회·동일 요청 재시도·성공 흐름과 360px 연결 도움말을 확인했다. 280px 가로 넘침은 없었다.
- 대시보드 콘솔 오류는 없었다. 확장 미리보기 로그에 발생 위치를 확인하지 못한 MutationObserver 오류 1건이 있었으나 확인한 흐름은 완료됐다. 실제 설치 확장→나라장터→NativeHost→DB 경로는 이번에 실행하지 않았다.
- 최종 정적 탐지 10건은 확장의 기존 테마 색·그림자·독립 글자 크기와 글꼴 이름 파싱 경고였다. 비활성 단추 hover 대비 지적은 제거됐다. 새 글꼴 파일이나 디자인 의존성은 추가하지 않았다.

## 구현 범위

기존 컴포넌트와 공유 토큰을 사용한다. 배치 편집·삭제와 현재 표 반출을 위한 백엔드 경로를 추가하되
데이터 모델·외부 소비 계약·파싱·문서 연결 판정은 변경하지 않는다. 계획·현황은 화면·처리·CLI 코드를
보존한 채 사용자 입구를 동결한다. 재개 지점은 `frontend/src/features.ts`의 `PLANNING_ENABLED`다.
원문 옆판과 신규 데이터 필터·열 숨기기는 이번 재설계 범위에 포함하지 않는다.

## 가공열 (2026-10-07)

최초 도입 시 설정 목차에 있던 가공열 편집은 현재 열 관리 작업공간으로 이동했다.
적용 대상·물품 필드·중복 제거·표시 서식·출력 방식을 고른다.
출력은 문자열 연결, 특정 행, 행 개수다. 최대 5건으로 미리 보고 저장하며 오류 시 초안을 유지한다.
정의 편집과 삭제는 읽기 전용 자료에서 잠긴다. 결과 셀은 직접 편집하지 않는다.
문서 생성기의 소비 규칙은 [데이터셋 규약](dataset-contract.md#사용자-정의-가공열-스키마-21)에 있다.

  UI 가공식 전달 오류와 저장 실패 시 초안 소실.
- 기존 소유 테스트 `UserColumnTests`에 7건, `SchemaBaselineTests`에 1건, `SettingsPanel.test.tsx`에 1건 추가.
  새 테스트 파일은 없으며 대체된 스키마·뷰 표면 스냅샷을 갱신했다. 제거할 중복 실행 사례는 없었다.
- 수집 사례 증감: 코어 +8, 화면 +1. 최종 코어 470건/43초, 화면 196건/21.06초 통과.

- 자동 테스트의 새 외부 자원 실행·의존성·CI 경로는 0개. coverage 기준 변경 없음.
